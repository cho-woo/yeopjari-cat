# 정지 경로 수정과 걷기 원화 검수 — v2.0.17 검토본

정지 오류의 코드 수정은 완료했다. **‘중간 발 자세가 이어지는 걷기 한 주기’의 원화 보강은 아직 완료하지 못했다.** 이미지 제작 도구로 실제 후보 48+64+16셀을 생성했지만 접지·비율·순환 연결 검수에 합격한 추가 제품 원화는 0장이다. 승인되지 않은 후보를 정상 원화로 교체하거나 연결 동작을 완료했다고 보고하지 않는다.

## 정지 오류의 원인과 수정

기존 `NativeGroundDriveReview`는 `DisplayedMotion(..., waiting=false)`와 `Evaluate(..., elapsed=0)`을 사용했다. 실제 앱의 SetMotion과 달리 정지 대기 진입·해제, 대기 중 동작 클록 정지가 없었다. 실제 Box2D 회귀 검사에서 60Hz 기준 **4417~4500ms**에 정면 중립 자세를 선택하는 구간을 재현했다.

실제 앱에서 4초에 정지를 요청하는 정상 경로는 180ms 안정 대기를 거쳐 이 틈을 통과한다. 그러나 **이미 현재 물리 속도만 0.5px/s 이하가 된 직후** 새 정지 행동을 요청하면, 기존 `NeedsStop`은 보간 표시 속도와 안정 시간을 확인하지 않아 대기를 놓칠 수 있었다. 따라서 진단에만 존재하는 문제라고 단정하지 않았다.

- `BeginGroundStop`: 현재 물리 속도·보간 표시 속도·안정 시간을 확인하는 정지 진입 조건을 공통화.
- `AdvanceGroundStop`: 대기 중 동작 시작/종료 시각을 함께 미루고 안정 상태에서만 해제.
- main·companion·진단이 같은 헬퍼와 순서를 사용. 진단의 동작 경과 시간도 실제 대기 클록으로 평가.
- 최근 보행의 첫100ms 정지 구간에는 마지막 측면 보행 자세를 유지. 이후 기존 측면 서기로 연결. 발을 회수하는 새 원화를 만든 것은 아니다.
- 수정 경로는 30/60/120Hz의 4.0~4.9초 구간에서 Walk 측면을 유지하는 회귀 검사를 통과했다. 정상 정지 요청·대기 없는 기존 진단·늦은 정지 요청을 모두 포함한다.

`stop-path-fixed.mp4`는 위쪽에 기존 진단 누락, 아래쪽에 공통 수정 경로를 보여준다. 원화·보폭·시나리오는 양쪽이 같다. 출력20FPS, 물리60Hz이며, 제품의 활동 갱신16ms(약60FPS)와 구분한다. 바탕화면 녹화가 아니다. `stop-path-4s-slow.mp4`는 문제 구간을 3배 느리게 보여준다.

## 실제 제작한 원화 후보와 판정

| 시도 | 실제 생성 결과 | 판정 |
| --- | --- | --- |
| 48셀 한 주기 | 새 다리·발 형태가 있지만 접지 발이 앞뒤로 반복 이동. 32→33·33→34를 접지에 맞추면 약312.5·294.1ms 유지 필요. 바닥 y154~158 변동 | 제품 교체 보류 |
| 64셀 한 주기 | 눈 중심은 약1.4~1.6source px 이내로 안정. 그러나 발 실루엣 위치 비교에서 전진24경계·거의 정지18경계. 후반 자세와 반복 연결 불일치 | 제품 교체 보류 |
| 16셀 원본4→5 연구 | 후반8장에 실제 후방 접지 중간 자세가 생김. 총 이동 약17.39논리px로 원본21.90px와 불일치, 최대 간격5.17px | 부분 작화 연구, 전체 주기 미승인 |

생성128셀은 승인된 고유 원화128장이라는 뜻이 아니다. 픽셀 해시가 달라도 올바른 새 발 자세라고 자동 판단하지 않는다. 실제 승인된 추가 제품 원화는 **0장**, 제품 Walk는 **8장**, 전체 실제 등록 원화는 **120장** 그대로다. 현재 도구는 지정한 네 발의 접지 궤적을 정확히 유지하는 결과를 만들지 못했다.

정속 비교 MP4 두 개는 같은 표시 높이110·같은 이동22px/s·같은 시나리오에서 후보의 문제를 드러내는 검수용 출력이다. 출력60FPS, 약5.83초/두 주기다. 후보는 균등 순서에 넣어 살펴본 **미보정·미승인 시트**이며, 균등화를 제품 보정 결과로 채택하지 않았다. 이 영상은 Pillow 합성이고 GDI+/Box2D 실행이나 바탕화면 녹화가 아니다.

## 보폭과 배분, 추가 제작 준비

제품의 보폭64px와 `[75,75,75,202,342,75,81,75]/1000`은 유지했다. 후보의 실제 네 발 ID·접지 연속성이 확정되지 않아 새 보폭을 임의로 산출하지 않았다.

`tools/calibrate_walk_contacts.py`는 앞으로 검수한 원화의 명시적 네 발 좌표·접지 여부·머리/몸통 기준점을 입력받는다. 마지막→첫 프레임까지 같은 발의 후방 이동으로 구간별 전진거리와 보폭을 구한다. 동시에 접지한 발끼리의 이동량 불일치, 앞으로 움직이는 접지 발, 바닥 오차, 머리/몸통 흔들림, 큰 중간 간격을 거부한다. 통과한 경우에만 importer용 매니페스트를 출력한다. 사람의 발 ID 주석이나 그림의 캐릭터 동일성까지 증명하는 도구는 아니다. 관련13개 자동 검사가 통과했다.

`original-walk-run-source.png`는 변경하지 않은 원본 시트이며 앞8셀만 Walk다. `original8-normalized-reference.png`는 같은 기준점·바닥선으로 표시한 참조다. 기존8장 기준은 공통 `anchor=(161,275)`, `referenceHeight=221`이다. 3→4→5 앞발 후보 중심은256→230→186source px다. 확실하지 않은 발 ID는 템플릿에서 null로 남겼다. 한 자세 유지 중 이동1논리px 이하를 목표로 하면 64px 주기에서 위상 간격1/64가 출발 기준이다. 64·96·128장 등 실제 간격과 시각 품질로 결정해야 하며, 장수만으로 충분하다고 승인하지 않는다.

## 다음 연결 동작 순서

걷기 주기가 검수를 통과한 뒤 아래 순서로 제작·연동해야 한다. 현재는 제작 명세이며 구현 완료가 아니다.

1. 마지막 접지 발을 지지한 채 반대 발 회수→네 발 정돈→측면 서기.
2. 측면 서기→앞/뒤 체중 이동→첫 발 들기→검수된 걷기 진입 위상.
3. 측면 정지→체중 이동→3/4→반대 측면. 현재 코드는 정지 후 좌우 반전만 한다.
4. 측면 서기→뒷다리 굽힘→엉덩이 접지→앞다리 정돈과 역순.

크림과 턱시도는 `AuthoredCharacter(8)=0`으로 같은 데이터·기준점·물리를 사용하고 캐시된 털색만 다르다. 이번 정지 수정은 둘 모두에 적용된다. 향후 카메라가 바뀌는 회전/앉기 원화는 고정된 측면 머리 코트 영역과 달라지므로, 새 클립 또는 명시적인 프레임별 머리/재질 등록도 함께 필요하다.
