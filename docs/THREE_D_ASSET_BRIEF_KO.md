# 옆자리 고양이 — 3D 캐릭터 제작 및 연동 요구사항

작성일: 2026-11-05. 이 문서는 제작 의뢰와 구현 검토를 위한 요구사항이며, 3D 전환이 완료되었다는 뜻은 아닙니다.

## 목표와 현재 상태

Windows 10/11 x64 바탕화면에서 사는 작은 고양이를 입체적인 골격 애니메이션으로 표현한다. 걷기·달리기·살금살금 접근·앞발 접촉·배 까기·창 사이 점프가 하나의 몸에서 연속적으로 이어져야 한다. 기존 캐릭터의 귀여운 인상과 작은 화면 크기에서의 가독성을 유지한다.

현재 구현은 Win32/GDI+로 2D PNG를 그리며, 부분 변형과 그림 사이 전환을 사용한다. Box2D는 동물의 물리 몸체와 창·바닥·장난감의 이동 및 충돌을 담당한다. 고양이의 척추·목·네 다리를 표현하는 3D 골격이나 3D 렌더러는 없다. 따라서 물리엔진을 사용한다는 사실만으로 입체적인 관절 움직임이 만들어지지는 않는다.

3D로 바꾸면 같은 몸을 연속적으로 회전하고 관절을 움직일 수 있다. 다만 자연스러움은 모델, 관절 배치, 관절에 따라 표면이 움직이는 가중치, 동작 제작, 전환, 접지 제어를 함께 검수해야 얻을 수 있다.

## 첫 납품 범위: 크림 치즈냥 한 마리

여러 종을 한꺼번에 제작하기 전에 한 마리로 실제 프로그램에서 품질을 확인한다. 기존 원화와 사용자 제공 영상은 외형·동작 참고 자료로 별도 전달한다. 정면뿐 아니라 옆면·뒷면·배·발바닥이 보이는 자세를 고려한다.

| 납품물 | 필요한 내용 |
| --- | --- |
| 편집 가능한 원본 | `.blend` 권장. 모델, 재질, 텍스처, 리그, 애니메이션을 수정할 수 있어야 한다. 외부 연결 파일도 함께 제공한다. |
| 실행용 모델 | glTF 2.0 `.glb`. 메시, 스킨, 변형용 뼈, 텍스처, 이름이 구분된 애니메이션 클립을 포함한다. |
| 사족보행 골격 | 몸통·골반·척추·목·머리, 네 다리·발, 양쪽 귀, 여러 마디 꼬리를 독립적으로 움직일 수 있어야 한다. |
| 스킨 가중치 | 목·어깨·골반·발목이 접힐 때 표면이 찌그러지거나 떨어지지 않도록 조정한다. 배를 보이는 자세에서도 검수한다. |
| 표정 | 눈 감기·졸림·편안함·놀람을 표현할 수 있는 얼굴 뼈 또는 표정 변형(shape key)을 제공한다. 귀 움직임 때문에 머리 전체 크기가 바뀌면 안 된다. |
| 동작 클립 | 아래 초기 검증 동작. 정지 이미지나 완성 영상만으로는 런타임 관절 제어를 할 수 없다. |
| 이용 범위 | 데스크톱 앱에 포함해 배포하고 수정할 수 있는 사용 권한이 확인된 자산을 제공한다. |

제작자가 사용하는 조작용 리그와 실행용 변형 골격은 구분한다. Blender의 제약·드라이버·시뮬레이션 결과는 필요한 키프레임으로 구워서 내보내고, 내보낸 GLB를 다시 불러와 동작을 확인한다. Blender에서만 작동하는 리그로 납품하지 않는다.

초기 모델은 일반 메시와 텍스처로 표현 가능한 스타일을 우선한다. 고비용 털 시뮬레이션은 첫 검증의 필수 항목이 아니다. 폴리곤·재질·텍스처 예산은 두 마리를 동시에 표시하는 실제 Windows 성능 측정 후 확정한다.

## 초기 검증 동작

| 클립 또는 구간 | 검수할 동작 |
| --- | --- |
| 기본 자세·주변 보기 | 호흡은 작게, 시선과 귀 움직임은 독립적으로. 턴마다 체격이나 머리 크기가 바뀌지 않는다. |
| 걷기·달리기·살금살금 | 서로 다른 보폭·발 순서·체중 이동. 지면에 붙은 발이 미끄러지지 않도록 접촉 시점을 제공한다. |
| 멈추기·방향 바꾸기 | 앉은 자세로 평행이동하지 않는다. 좌우 전환 때 몸이 즉시 뒤집히지 않는다. |
| 앞발 들기·톡톡 치기·냥냥펀치 | 몸을 지지하는 발에 체중을 싣고, 다른 앞발이 목표에 닿았다 돌아온다. |
| 옆으로 눕기 → 배 보이기 → 일어나기 | 머리·목·등이 연속적으로 움직인다. 누운 방향에 맞게 옆얼굴과 뒷머리가 보이고, 목을 과도하게 비틀거나 뒤로 공중회전하지 않는다. |
| 점프 준비·도약·공중·낙하·착지 | 구간을 분리하여 비행 시간이 달라져도 연결할 수 있게 한다. 착지할 때 다리가 충격을 흡수한다. |
| 귀 움직임·눈 깜빡임 | 몸과 머리 전체를 늘이거나 줄이지 않고 국소적으로 움직인다. |

반복 동작은 마지막과 처음 프레임이 자연스럽게 연결되어야 한다. 걷기·달리기는 제자리 클립을 기본으로 하고 기준 속도·보폭을 함께 제공한다. 점프의 실제 이동 경로는 프로그램의 물리 계산이 결정한다. 일회성 동작에는 시작·끝 자세와 루프 가능 구간을 명시한다.

루트와 바닥 높이, 전방 방향, 스케일을 모든 클립에서 통일한다. glTF 좌표 변환은 exporter에서 처리하고, 발 접촉·이륙·착지·앞발 접촉의 시간을 문서나 별도 메타데이터로 제공한다. 일반적인 동작 중 음수 스케일 반전이나 몸 전체 크기 변화에 의존하지 않는다.

위 목록은 3D 품질을 판단하기 위한 첫 단계다. 실제 제품 전환 전에는 몸단장·기지개·식빵·꾹꾹이·긁기·하품·재채기·수면·먹기·장난감·희귀 행동·두 동물 상호작용 등 현재 기능에 대응하는 동작도 갖춰야 한다. 첫 모델의 일부 동작만 완성된 상태로 기존 기능을 없애거나 완성판으로 배포하지 않는다.

## 프로그램에서 구현할 부분

- Windows 투명 창에서 골격과 표정이 있는 3D 모델을 그리는 렌더러를 추가한다. 기존 C++ 호스트와 연결하는 Direct3D 11은 검토 가능한 방식이며, 아직 구현·성능 검증된 선택은 아니다.
- Box2D를 유지하여 바탕화면 평면상의 위치·속도·중력·창 충돌을 계산한다. 모델의 골격은 그 결과를 따라 그린다. 화면 안쪽 깊이 방향의 이동은 현재 기능에 필수적이지 않다.
- 실제 이동 거리와 지지 창의 이동을 반영해 보행을 동기화하고, 발이 닿은 동안 접점을 유지하도록 다리 관절을 조정한다(발 IK). 머리·척추의 회전 범위도 제한한다.
- 서기·앉기·눕기마다 발·배·등 등 지지 부위와 충돌 범위를 맞춘다. 같은 충돌 몸체에 모델만 덮어씌우는 것으로 접지 문제를 해결했다고 보지 않는다.
- 상태와 자세를 연속적으로 연결한다. 목적지 창이 움직이거나 닫히면 물리 계산에 따라 떨어지고, 실제 접촉이 생겼을 때 착지 동작을 재생한다. 공중 동작의 시간이 끝났다는 이유로 착지 자세에 고정하지 않는다.
- 귀·꼬리에는 필요한 만큼만 관성 표현을 추가한다. 전신을 물리 관절에 맡기는 래그돌은 기본 생활 동작의 대체 수단으로 삼지 않는다.
- 저장된 생일·성장·체형·캐릭터 ID·성격·친밀도·기억·두 번째 동물과 업데이트 설정을 보존한다. 모델별 매핑과 성장·체형 표현도 검수한다.
- 무음, 자동 행동, 캐릭터 선택, 밥·츄르, 커서 놀이 설정을 유지한다. 제거한 옷장을 다시 넣지 않는다. 커서 놀이는 실제 OS 포인터를 이동하거나 입력을 발생시키지 않는다.

## 통합 후 통과해야 할 검수

1. 실제 바탕화면 표시 크기에서 옆·정면·뒤쪽과 배 까기 영상을 검토한다. 목 꺾임, 몸 크기 변화, 관절 찌그러짐, 발 미끄러짐, 바닥 뚫림, 자세 전환 끊김을 확인한다.
2. 걷기·달리기·살금살금의 출발·정지·방향 전환과 행동 중단·재개를 확인한다. 느린 속도에서도 발 움직임만 과장되지 않아야 한다.
3. 창 이동·크기 변경·최대화·닫힘을 점프의 여러 시점에 발생시킨다. 도달하지 못하면 낙하하고, 실제 창이 없는 옛 위치에서 서 있지 않아야 한다.
4. 커서에 접근해 실제 앞발 끝을 목표 방향으로 움직이는지, 모드 OFF와 커서 이탈에 맞게 중단하는지 확인한다.
5. 두 마리, 성장·체형, 여러 DPI·모니터, 다른 프레임 간격에서 기능과 표시를 검수한다. 최소 지원 GPU와 부하 목표는 렌더러 시제품 측정 후 확정한다.
6. 기존 저장 파일 호환성·업데이트, Windows x64 빌드와 실제 실행, 모델 포함 ZIP, 업데이트 피드 검증을 통과한 산출물만 배포한다.

## 사용자와 제작자의 준비 범위

사용자가 직접 Blender를 배우거나 외부 모델을 먼저 구해 와야 하는 것은 아니다. 현재 개발 환경에서 Blender 4.3.2를 실행할 수 있으며, Python으로 모델링·골격·가중치·애니메이션 제작과 렌더링을 직접 진행할 수 있다. 첫 직접 제작 결과는 [3D 시제품 기록](THREE_D_PROTOTYPE.md)에 정리한다. 이 문서로 외부 제작을 의뢰하거나 적합한 모델을 구입해 수정하는 것도 가능하다. 구입품에 필요한 동작이 빠져 있다면 애니메이션 추가 작업이 필요하다.

초기 자산 목표는 **크림 치즈냥 한 마리의 편집 가능한 원본과, 골격·가중치·초기 동작이 포함된 GLB**다. 직접 제작과 외부 자산 모두 같은 검수 기준을 적용한다. 외형은 기존 캐릭터와 참고 영상으로 맞추고, 먼저 프로그램에서 검수한 뒤 다른 종으로 확대한다. 체격이 비슷한 고양이는 골격을 공유할 수 있지만 먼치킨·강아지·토끼는 비율과 보행에 맞춘 조정이 필요하다.

개발 측에서는 모델 검사·로딩, 렌더링, 관절 제어, 물리 연동, 행동 전환과 호환성 검증을 구현한다. 간단한 시제품은 만들 수 있지만, 코드나 생성 이미지·영상만으로 완성도 높은 캐릭터 모델과 애니메이션이 자동으로 확보되는 것은 아니다. 3D 생성 서비스를 사용할 때에도 위 납품 파일이 실제로 나오는지 먼저 확인한다.
