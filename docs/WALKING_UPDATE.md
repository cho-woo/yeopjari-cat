# 보행 개선 검증 — 2.0.16

크림치즈냥과 턱시도냥의 기존 원화와 얼굴을 유지하고, 실제 접지한 이동·감속·정지·반전을 연결한다. 별도 부위 리그나 새 캐릭터 그림을 도입하지 않았다. 이 문서는 원화의 한계와 구현 검증을 구분한다.

## 확인한 현재 구조

C++17 / Win32 layered window / GDI+ / Box2D(C17). `build.sh`는 고정된 llvm-mingw와 Box2D로 x64 Windows EXE를 만든다. 물리는 1/60초 고정 스텝과 4개 Box2D 하위 스텝, 표시는 보간한 위치를 사용한다. 보행도 같은 보간 위치에 대응하는 누적 지상 이동거리로 진행한다. 픽셀 위치는 논리 px → 성장·체형 → 모니터 DPI 순서로 변환한다.

9개 PNG, 10개 클립, 실제 원화 120장이다. 걷기 8장·뛰기 8장은 하나의 4×4 시트 앞/뒤 절반이다. 그루밍 16, 수면 8, 박스 8, 생선 8, 펀치 12, 사료 12, 점프 16, 츄르 24장은 그대로다. 두 캐릭터는 같은 프로그램·기준점·재생 순서를 공유하고 털색 캐시만 다르다.

현재 상한은 이미 원화 256장, 재생 항목 512개다. 기존 8/12/16/24장과 합성 64/128/256장 호환 검사는 유지했다. 그림을 복제해서 고유 원화 수를 늘리지 않았다.

## 수정한 문제

- 이전 누적 보행거리는 공중의 x 이동도 더했다. 한 표시 틱 안에 낙하와 착지가 함께 발생하면 최종 grounded만 검사하여 공중 거리가 보폭으로 들어갔다. 이제 같은 지지면에 연속 접촉한 물리 스텝만 누적한다. 움직이는 창이 운반한 거리는 뺀다.
- 반대 방향 속도를 바로 모터에 넣던 경로에 공통 `GroundDrive`를 연결했다. 물리 속도와 보간 표시 속도가 모두 0.5 논리 px/s 이하가 된 뒤 180ms 안정, 반전 후 120ms 유지한다. 이동 중 같은 방향의 속도 변경은 위상을 초기화하지 않는다.
- 화면·창 가장자리에서는 제동거리와 12px 여유를 사용하여 미리 감속한다. 충돌로 멈춰도 가짜 시간 기반 발걸음을 만들지 않는다.
- 정지 후 100ms부터 같은 걷기 시트의 서 있는 0번을 표시한다. Idle/Watch에서는 정지 후 최대 1.2초 동안 옆모습을 유지한다. 다시 걷기 시작하면 안정된 첫 자세로 시작한다. 서기→앉기의 새 중간 원화를 만든 것은 아니다.
- 실제 두 캐릭터의 행동 연결에서 완성된 이미지 두 장을 합성하던 페이드를 제거했다. 기존 리소스를 사용하는 내부 검증용 경로는 별도다. 실행 경로에서 불필요한 3장 화면 캡처·복사와 스타일 블렌드 버퍼 할당도 생략한다.
- `standing_frame`을 매니페스트·생성 헤더·검증에 추가했다. 소품/꼬리 경계에 따라 매 프레임 크기를 다시 맞추지 않는다. 기존 프레임 rect/anchor와 동작별 공통 referenceHeight, 격리한 프레임 알파는 유지한다.

## 보폭 설정과 원화 한계

걷기 기준 높이는 221 원본 px, 성체 표시 높이는 110 논리 px다. 269–274행의 알파 200 이상 발바닥 픽셀과 원화를 대조하면 가까운 앞발의 접지 중심은 3번 약 x256, 4번 x230, 5번 x186이다. 두 접지 변화는 표시 크기에서 약 12.94px, 21.90px다.

한 주기는 **64 논리 px**(기존 72), 접지 구간 3→5에 약 54.4%를 배정했다. 전체 구간 비중은 `[75,75,75,202,342,75,81,75]/1000`이다. 해당 두 접지 경계에서 이동거리는 12.93px, 21.89px다. 이 수치는 전후 원화의 접지 위치 차이를 맞춘 보정이다. 단일 원화를 유지하는 동안의 발 미끄러짐까지 제거했다는 뜻은 아니다. 뛰기 150px와 60/45px/s 진입·이탈 히스테리시스는 유지했다.

Walk/Run의 `ms`는 거리에 대응하는 구간 비중이며, 실제 초 단위 재생 속도는 이동거리로 결정된다. 예를 들어 22px/s에서 걷기 한 주기는 약 2.91초다. 8장 원화와 활동 시 16ms(~60Hz) 화면 갱신은 별개다. 같은 그림을 더 자주 그려도 그 사이의 발 자세가 새로 생기지는 않는다.

**남은 원화 제작:**

- 걷기: 현재 8개 키 포즈 사이, 특히 3→4→5 접지 중 앞·뒷발이 몸에 대해 일정하게 뒤로 이동하는 자세를 포함해 24–32장 순환 원화. 같은 옆모습 머리·몸통 위치, 지면, 체형을 고정하고 마지막→첫 프레임도 연결.
- 출발/정지: 양 방향에서 체중 이동→첫 발 들기, 마지막 발 회수→네 발 모으기의 4–6개 자세, 각 0.15–0.3초.
- 서기↔앉기: 뒷다리 굽힘→엉덩이 접지→앞다리 정돈 및 역순, 옆/3/4 시점 각 6–10장, 0.4–0.7초. 현재 정면 앉기와 옆면 서기 사이 시점 변화도 원화로 연결해야 한다.
- 회전: 뒤꿈치/엉덩이 중심 체중 이동→3/4→반대 옆면, 6–8장, 0.3–0.5초. 현재는 정지한 뒤 좌우 반전한다.
- 뛰기: 8장의 긴 다리 이동/비행 사이에 접지·회수 자세 추가. 물리 점프 높이를 그림에 중복 적용하지 않도록 공통 root 유지.

## 검증 자료

`native_ground_drive_tests.hpp`는 실제 Box2D로 정지 → 22px/s → 42px/s → 정지 → -28px/s → 정지 없는 반대 요청 → 정지를 재현한다. GDI+로 두 캐릭터를 그리며 100/125/150%는 **합성 DPI 배율 검사**다. 상단 비교는 v2.0.15의 동일 원화/균등 진행/72px/직접 반전 로직 재현이고, 하단은 현재 코드다. 데스크톱 화면 녹화 또는 구버전 EXE의 녹화라고 표시하지 않는다.

[최종 소스 검증](https://github.com/cho-woo/yeopjari-cat/actions/runs/42559903373)은 커밋 `8ae8734ab081d27eb9d5cec51fe082310e46df47`에서 Linux 검사/Windows x64 빌드 및 Windows Server 2022 네이티브 실행 검사를 모두 통과했다.

- `tools/check.sh`: 기존 저장·돌봄·행동·물리·커서 검사, 매니페스트/이미지 검증, Windows EXE·ZIP·업데이트 피드·무음 검사 통과.
- 새 실제 Box2D 시나리오: 30/60/120Hz 입력에서 출발·속도 변경·정지·반전, 정지 유지, 공중 이동 제외, 30초 지연 및 좌표 재배치 검사 통과.
- Windows `--self-test`: 저장·메뉴·커서·창 이동 회귀 검사 통과. `--render-self-test`: 실제 GDI+ 보행/접지/착지/두 털색, 투명 픽셀 및 잘림, 캐시·64/128/256장 합성 자산 검사 통과. [네이티브 결과](validation/v2.0.16-render-self-test.txt).
- 100/125/150% 합성 DPI 검사에서 정지·반전 위치와 그리기를 확인했다. 원화의 공통 기준점·referenceHeight와 캐시 픽셀 수는 유지한다. 실제 배율이 다른 두 모니터와 물리 마우스로 창 밖까지 드래그하는 사용감은 수동 확인하지 못했다.
- [재생 가능한 비교 페이지](walking-preview.html), [MP4](media/walking-native.mp4), [GIF](media/walking-native.gif). 210개 실제 Windows 출력 프레임, 10.5초/20FPS이며, Chromium에서 마지막까지 재생과 오류 없음 확인. [브라우저 검사](validation/v2.0.16-preview.json). 비교 상단은 이전 로직 재현, 하단은 수정 코드다.

## 동일 Windows 환경에서 측정한 성능

같은 실행기(논리 CPU 4개, 1024×768/96DPI), 같은 신규 기록 복사본, 실행파일을 미리 읽은 파일 캐시 조건으로 v2.0.15 공개 EXE와 검증한 v2.0.16 EXE를 한 번씩 순서대로 실행했다. 250ms 간격으로 프로세스 카운터를 읽었다. CPU는 **한 코어를 100%로 본 값**이다.

| 항목 | v2.0.15 | v2.0.16 |
| --- | ---: | ---: |
| 보이는 창까지 시작 시간 | 1,375.22ms | 1,379.81ms |
| 쉬기 8초 평균 CPU | 0.387% | 0.194% |
| 쉬기 해제 후 12초 평균 CPU | 0.000% | 0.129% |
| 쉬기·재개 6회 평균 CPU | 0.276% | 1.087% |
| 시작 시 Private 메모리 | 184.11MiB | 183.00MiB |
| 전체 관찰 중 최대 Private 메모리 | 184.31MiB | 183.20MiB |
| OS 최대 Working Set | 212.77MiB | 211.94MiB |
| 6회 반복 구간 Private 증가 | 0바이트 | 0바이트 |

자율 행동의 종류·실제 보행 시간은 고정하지 않았다. 특히 이전 버전의 12초 CPU가 계측 해상도에서 0으로 나온 만큼 **이 구간을 지속 보행 부하 시험으로 취급하지 않는다**. 반복 구간 CPU도 새 버전이 높게 관찰됐으며, 한 번의 짧은 실행으로 성능 개선/악화를 단정하지 않는다. 실제 장시간 보행 CPU·프레임 지연 분포·장시간 누수는 미검증이다. [전체 측정값과 조건](validation/v2.0.16-benchmark-result.json).

UI Automation의 하위 메뉴 캐릭터 선택은 저장 결과로 확인되지 않아 반복 측정에 사용하지 않았다. 양 버전에서 `paused` 저장값으로 확인되는 최상위 쉬기/재개 메뉴를 6회 반복했다. 두 캐릭터 렌더링/캐시 검사는 별도 네이티브 검사를 사용한다.
