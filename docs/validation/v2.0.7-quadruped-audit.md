# v2.0.7 사족보행 관찰

대상: 크림·실버의 일반 걷기. 런타임이나 원본 그림을 바꾸지 않고 v2.0.7의 실제 첫 네 그림과 렌더 경로를 확인했다. 비교 도구의 이미지 혼합 제거와 네 발 보행의 자연스러움은 별개의 문제다.

## 실제로 남아 있는 문제

1. **접지 중인 발이 몸과 함께 미끄러진다.** `Evaluate(..., Locomotion)`는 이동 14 body px당 원본 네 장을 순환한다. 한 장이 유지되는 동안 발의 몸 기준 좌표는 고정인데 Box2D의 몸 위치는 계속 움직인다. 따라서 바닥을 짚고 있어야 할 발도 몸과 함께 옮겨진다. 한 그림 구간은 3.5 body px, 성체 22px/s에서는 약159ms다. 정지할 때 순환을 멈추는 검사는 통과해도, 이동 중 접지가 맞는다는 뜻은 아니다.
2. **네 발의 접지와 회수가 독립적으로 제어되지 않는다.** 전체 그림 한 장을 한 번에 바꾸므로 뒷발을 지탱하고 앞발을 회수하는 구간을 개별적으로 만들 수 없다. 원본0·2번은 모두 가까운 앞발을 앞으로 든 형태이며, 뒷발의 전후 이동은 매우 작다. 그림 순서를 바꾸는 것만으로 완전한 사족보행 주기를 얻기 어렵다.
3. **자세 사이의 순간 변화가 남는다.** 혼합을 제거해 이중 얼굴은 없어졌지만, 각각 그려진 얼굴·몸·발 윤곽이 약159ms 간격으로 통째로 바뀐다. 이동은 부드럽고 발은 갑자기 바뀌어 두 속도가 맞지 않는다.

## 원본의 가까운 뒷발 위치 측정

`tools/render_motion_preview.py:atlas`와 같은 규칙으로 alpha≤16인 픽셀을 제거하고 기본 시트 0–3번을 자른다. 각 그림을 420×460 캔버스의 `(210,440)` 바닥 중앙에 놓는다. 가까운 뒷발 영역 `x=40..134, y=385..439`에서 alpha>153인 픽셀을 고르고, 가장 낮은7행의 평균 x를 발끝 위치의 대리 지표로 삼았다. y=438은 아래2px 투명 여백을 뺀 기준선이다. 모든 좌표는 `110 / max(원본0–5번의 crop 높이)`로 body px에 환산한다.

이는 접촉 센서나 골격 랜드마크가 아니라 **같은 발 윤곽이 그림 사이에서 실제로 얼마나 옮겨졌는지** 확인하는 영상 측정이다. source sole의 높이 차이는 원본 그림의 발 들림과 crop 여백을 포함한다.

| 캐릭터 / 그림 | 뒷발끝 x(body px, 중심 기준) | 기준선 위 발끝 높이(body px) |
| --- | ---: | ---: |
| 크림0 | -32.93 | 0.30 |
| 크림1 | -32.75 | 2.40 |
| 크림2 | -33.94 | 0.60 |
| 크림3 | -33.66 | 1.50 |
| 실버0 | -36.63 | 0.37 |
| 실버1 | -36.25 | 1.85 |
| 실버2 | -35.55 | 0.37 |
| 실버3 | -35.11 | 2.96 |

한 주기 동안 뒷발끝의 몸 기준 x 범위는 크림1.19px, 실버1.52px다. 반면 몸은14px 전진한다. 특히 원본0·2번처럼 뒷발이 바닥 가까이에 있는 그림을 유지하는 동안에도 발끝이 최대3.5px씩 앞으로 끌려간다. 현재 이미지의 전후 폭 변화는 이 이동을 상쇄하지 못한다.

재현 명령(저장소 루트):

```python
import sys
sys.path.insert(0, 'tools')
from render_motion_preview import atlas
from PIL import Image
for name in ['cat.png', 'cat-silver.png']:
    frames, _ = atlas(name)
    scale = 110 / max(im.height for im in frames[:6])
    for i, im in enumerate(frames[:4]):
        canvas = Image.new('RGBA', (420, 460))
        canvas.alpha_composite(im, (210-im.width//2, 440-im.height))
        alpha = canvas.getchannel('A')
        points = [(x, y) for y in range(385, 440) for x in range(40, 135)
                  if alpha.getpixel((x, y)) > 153]
        sole = max(y for x, y in points) + 1
        toe = [(x, y) for x, y in points if y >= sole-7]
        x = sum(x for x, y in toe) / len(toe)
        print(name, i, round((x-210)*scale, 2), round((438-sole)*scale, 2))
```

## 이전 다리 변형 코드의 주의점

`src/cat_gait.hpp`의 느린 보행 위상은 가까운 뒷발 → 가까운 앞발 → 먼 뒷발 → 먼 앞발의 순환과 좌우 반 주기 차이를 표현할 수 있다. 접지 중 발이 몸의 실제 이동만큼 반대쪽으로 옮겨져야 한다는 계산도 있다. 그러나 그림을 분리·합성하는 단계가 이를 실제 발로 보여 주어야 한다.

`src/cat_locomotion_rig.hpp`의 이전 inverse warp를 그대로 다시 켜면 안 된다.

- 무릎 방향이 `i==0 ? +1 : -1`이라 가까운 뒷발과 먼 뒷발의 굽힘 방향이 달랐다. 다리 인덱스는0·1이 뒷다리,2·3이 앞다리다.
- 발의 원래 위치와 관절 길이 대신 가정한 `restX`와 세로 root를 사용해 발을 원본 자세보다 과하게 뻗을 수 있다.
- 이동한 다리 아래의 torso 분리 경계에 빈 영역이 드러나 삼각형 구멍처럼 보이는 현상이 실제 v2.0.5 비교 이미지에 남아 있다. 발 좌표 검사만으로 이 합성 결함은 잡히지 않는다.

## 수정 판단 기준

한 장의 원본 얼굴·몸통을 기준으로 네 발의 지지/회수 순서를 제어하고, 지지 중인 발은 바닥의 같은 위치에 두며, 회수할 때만 낮은 곡선으로 앞으로 옮겨야 한다. 앞다리와 뒷다리는 서로 다른 관절 굽힘을 가지되 좌우 같은 종류의 다리는 같은 해부학적 방향을 사용한다. 발바닥·발등은 함께 이동해 발 모양을 유지한다. 이 숫자 조건뿐 아니라 다리 뿌리의 연결, 가려짐, 빈틈, 원본 털 윤곽을 실제 전체 주기 이미지로 확인해야 한다.

이 보고서는 개선의 원인 분석이며 자연스러운 보행 구현이나 Windows 실행 검증을 완료했다는 보고가 아니다.

## 후속 관절 후보의 독립 시각 검토

위 분석에 따라 제작한 관절 후보를 `build/articulated-walk/candidate.gif`의 뼈 선을 표시하지 않은 출력으로 별도 확인했다. 크림·실버 각각0.00,0.08,0.16,0.24,0.32,0.40,0.48,0.56,0.64,0.72,0.80,0.88초의12개 표본을 확인했다. 후보의 실 보행 주기는18 body px이며 각 발의 지지 비율은0.72, 회수 높이는2.6 body px다. 발 좌표에 배율을 곱하지 않고 실제 이동만큼 접지 좌표를 보정한다.

초기 후보에서 발견한 문제는 다음과 같이 교정된 후 다시 살폈다.

- 먼 다리를 작게 그리면서 뿌리 높이를 그대로 두어 발이 바닥에 닿지 못하던 문제: 다리 길이·뿌리 위치를 조절하고 도달 오차를 검사한다.
- 수학적 발바닥과 실제 그림의 가장 아래 픽셀 차이: 각 다리 마스크의 alpha>153 실제 sole을 측정해 등록한다.
- 목 아래에 추가 팔처럼 남던 가슴 조각과 뒤로 튀어나온 엉덩이 경계: 앞다리 마스크에서 목을 제외하고, 몸통 아래를 둥글게 정리하며 가까운 뒷다리의 겹침 순서를 바꾼다.

최종 후보에서는 이전의 명백한 분리된 가슴 조각·삼각형 빈틈을 정상 표시 크기와2배 표본에서 찾지 못했다. 네 발이 서로 다른 시점에 들리고 앞으로 회수되며, 얼굴은 하나의 원본을 유지한다. 지지 중인 발이 고정된 원본 그림과 함께 끌려가던 v2.0.7보다 보행 연속성이 개선됐다.6배 확대에서는 작은 손목 털 돌기가 보이지만 분리된 추가 팔다리처럼 보이지 않아 통합을 막는 결함으로 판단하지 않았다.

몸통의 체중 이동은 아직 작은 만화식 표현이다. 이 관찰은 완전한 생물학적 재현이나 모든 모션·모든 표시 크기의 자연스러움을 보장하지 않으며, Windows 네이티브 실행·저장·업데이트·패키지 검사는 별도다.
