# v2.0.8 걷기·달리기의 동작 연출 검토

2026-11-06(한국 시간). 아래 원인 분석은 변경 전 v2.0.8 코드의 읽기 검토와 정적 접지 표본이다. 이후 사용자가 직접 제공한 걷기8자세·달리기8자세 참고 시트를 바탕으로 [v2.0.9 구현](../V2_0_9.md)을 진행했다. 원인 분석 당시의 수치와 제안을 구현 완료 수치로 읽지 않도록 구분한다.

사용자가 보낸 Pinterest 세 주소는 현재 클라우드 네트워크에서 403으로 차단됐다. 따라서 아래 제안은 링크 속 동작을 보았다는 주장이나 해당 작품을 재현했다는 검증이 아니다. 후속 참고 시트는 확인했으며 걷기의 안정된 몸통·순차 회수, 달리기의 모으기·펴기와 꼬리 방향을 구현 기준으로 삼았다. 정지 시트로 동영상의 정확한 시간 간격까지 측정할 수는 없다.

## 현재 걷기가 아직 기계적으로 보일 수 있는 이유

`Locomotion`의 별도 `jointCycle_`은 18px 보폭, 접지 비율0.72, 발 들림2.6px를 사용한다. 크림·실버의 일반 걷기는 `DrawJointWalkingPet`에서 새 관절 렌더러를 사용하므로, v2.0.7의 그림 네 장 교체와 달리 발 접지를 실제 그림에 반영한다. 이 개선은 유지해야 한다.

그러나 `cat_articulated_walk.hpp`는 매 프레임 원본 그림 위쪽68%를 그대로 복사한다. 어깨와 골반의 뿌리도 고정이고, 몸통 판 역시 준비 단계에서 만든 정적인 그림이다. 따라서 다음 요소가 빠져 있다.

- 지지하는 다리의 굽힘에 따른 어깨·골반의 작은 높이 변화.
- 견갑골이 앞뒤로 미끄러지는 느낌과 골반의 약한 반대 위상 움직임.
- 몸이 다리를 넘어가는 접지 전반·후반의 체중 이동.
- 걷기와 달리기에서 서로 다른 허리의 모으기·펴기.

발 들림2.6px는 이 캐릭터의 약100px 높이 중2.6% 정도다. 실제 크기에서는 발이 조금만 떠서, 걷는 자세보다 몸 아래에서 짧게 발을 흔드는 느낌이 남을 수 있다. 성체22px/s에서 한 주기는 약0.818초이고 회수 구간은 약0.229초다.

## 현재 달리기는 갤럽이 아니라 빠른 대각선 속보에 가깝다

달리기 `Zoomies`는 새 관절 렌더러를 사용하지 않고 기존 `cat_locomotion_rig.hpp`의 inverse warp로 간다. `ForSpeed`의 빠른 값은 보폭52px, 접지 비율0.54, 발 들림4.8px다. 이때 `LegPhase`는 다음 대각선 쌍을 같은 위상에 둔다.

- 가까운 앞발 + 먼 뒷발.
- 먼 앞발 + 가까운 뒷발.

또한 `FootAt`가 접지 비율을 최소0.5로 제한하므로, 이 대각선 패턴에서는 네 발이 모두 떠 있는 구간이 생기지 않는다. 빨리 재생해도 허리를 모았다 펴는 고양이의 갤럽과 같은 동작이 되지 않는다.

현재 코드로 10,000개 위상을 표본 추출한 정적 지지 분포:

| 프로필 | 두 발 지지 | 세 발 지지 | 네 발 지지 | 네 발 모두 공중 |
| --- | ---: | ---: | ---: | ---: |
| 걷기18 / .72 / 2.6 | 12% | 88% | 0% | 0% |
| 빠른52 / .54 / 4.8 | 92% | 0% | 8% | 0% |

이는 `FootAt(phase + LegPhase(leg,duty),...)`를 정적으로 평가한 비율이다. 속도 전환 중 접점 재배치나 실제 Box2D 비행을 측정한 결과는 아니다.

기존 inverse warp에는 무릎 방향을 `i==0 ? +1 : -1`로 정하는 코드가 남아 있다. 인덱스0·1이 뒷다리이므로 먼 뒷다리만 앞다리와 같은 방향으로 굽히는 차이가 있다. 이 경로를 계속 사용할 경우 고쳐야 할 구체적인 문제다.

## 제안하는 자세 구성

### 느린 걷기

현재의 같은 쪽 뒷발 → 앞발 → 반대쪽 뒷발 → 앞발 순서와 실제 지지점은 유지한다. 발이 아니라 **몸통·관절 뿌리가 지지점을 지나가게** 해야 한다.

1. 접촉: 발바닥이 먼저 안정되고 어깨·골반이 조금 내려가며 무게를 받는다.
2. 중간 지지: 몸이 발 위를 지나가고 다리의 굽힘이 줄어든다.
3. 밀어내기: 뒤쪽으로 남은 발이 몸을 보내고, 발목이 먼저 풀린다.
4. 회수: 발을 낮게 접어 앞으로 보낸다. 들림의 정점은 회수 구간 중간보다 조금 앞에 두고, 착지 전에는 내려오는 시간을 준다.

초기 실험 범위는 발 들림3.5–4px, 어깨·골반 높이 변화0.4–0.8px, 몸통 기울기0.3–0.6도 정도가 적절하다. 이는 확정값이 아니라 작은 캐릭터에서 과장을 줄이기 위한 출발점이다. 모든 자세에서 IK 도달과 실제 발 그림의 바닥 접촉을 다시 확인해야 한다.

얼굴을 다른 그림으로 바꾸거나 키를 늘였다 줄이는 처리는 피한다. 머리는 같은 그림을 강체로 유지하고 몸통의 작은 변화에 반대 자세를 주어 시선이 안정되게 한다. 상체 그림을 고정하더라도 어깨·골반 뿌리와 몸통 아래 부분을 움직이면 현재의 얼어붙은 몸통 느낌은 줄일 수 있다.

### 빠른 속보

걷기를 단순히 두 배 빠르게 재생하지 않는다. 대각선 두 다리의 지지를 사용하되 접지 시간이 짧아지고 발 회수·어깨 눌림이 더 뚜렷해지도록 한다. 발 모양은 강체를 유지하고 발의 목표 좌표를 축소해 보폭을 줄이면 안 된다. 보폭·주기를 바꾸려면 접지 제어기 자체의 매개변수를 바꿔야 한다.

### 고양이의 빠른 달리기/갤럽

실제 참고 자료를 확보한 뒤, 선행 다리의 방향을 포함해 다음 네 핵심 자세를 먼저 정한다.

1. 앞발 착지와 어깨의 무게 받기.
2. 뒷발을 배 아래로 모으면서 허리 굽히기.
3. 뒷발 밀어내기와 몸통 펴기.
4. 다음 착지로 이어지는 뻗은 자세.

이 패턴에는 앞발·뒷발의 접촉 묶음, 짧은 위상 차이, 허리 모으기·펴기와 공중 구간이 필요할 수 있다. 속보의 위상에 전신 회전만 더해서는 같은 동작이 되지 않는다.

네 발이 실제로 모두 뜨는 달리기를 넣는다면 Box2D의 뿌리 높이·비행 상태와 발의 지지를 함께 연결해야 한다. 바닥을 지지하는 물리 상태를 유지한 채 그림만 떠다니게 만드는 것과 구분해야 한다. 우선 지면을 유지하는 속보의 완성도를 높이고, 참고 영상에 공중 구간이 확인될 때 실제 비행 제어를 추가하는 경로가 안전하다.

## 구현·검토 기준

- 몸통의 높이·기울기를 추가해도 접지 발의 세계 좌표는 변하지 않아야 한다. 전체 비트맵을 위로 움직일 때는 발 목표를 정확히 반대로 보정해야 한다.
- 어깨·골반 이동은 IK 목표가 아니라 관절 뿌리에 적용한다. 발바닥이 목표와 다르게 움직이면 계산만 맞고 그림은 미끄러지는 문제가 재발한다.
- 자세 구간은 정지·재출발·가감속에서도 이어져야 한다. 행동 시계가 다시 시작됐다고 발이 되감기면 안 된다.
- 무릎/팔꿈치와 손목/발목이 같은 관절처럼 접히지 않게 위·아래 다리와 발의 역할을 구분한다.
- 본선 없이 실제 크기로 본 걷기·속보·빠른 달리기의 인상이 서로 달라야 한다. 관절 선이 올바르다는 숫자만으로 자연스러움을 판정하지 않는다.
- 원본 크림·실버, 마름·보통·통통함, 양방향, 바닥·창 지지, 착지 직후와 두 마리를 검토한다.

현재 v2.0.8의 발 접지는 유용한 기반이지만, 참고 애니메이션처럼 느껴지려면 몸통의 무게와 동작별 자세 연출이 추가로 필요하다.


## v2.0.9 구현과 후속 검증

걷기에는 몸통과 어깨·골반의 작은 움직임을 추가하고 발 들림을 3.1px로 조절했다. 우다다는 별도 갤럽 순서와 42px 보폭·.32 지지 비율·8px 회수 높이를 사용한다. 앞발이 0/.10에서 먼저 착지하고, 뒷발이 .50/.60에서 뒤따른다. 아래쪽 허리만 작게 모았다 펴며 머리의 눈·입 거리는 같은 강체 변환으로 유지한다. 꼬리도 원본 털 조각을 회전한다.

몸통 변환은 관절 뿌리에 적용하고 발 목표는 지면 좌표에 남긴다. 걷기↔달리기의 `Configure()`는 제어기를 초기화하지 않는다. 기존 지지점, 이미 진행 중인 회수 곡선과 위상을 유지하고, 새로운 중립 위치는 다음 발걸음에서 적용한다. 실제 이동 속도 35px/s 초과에서 달리기로, 30px/s 미만에서 걷기로 이어간다. 전환 중 발이 하나라도 지지하면 공중 자세 가중치는 0이다. 실제 Box2D 바닥·창 지지와 점프 제어는 변경하지 않는다.

초기 전환 검토에서 보폭과 지지 비율의 보간값을 곱한 결과가 일시적으로 커져, 마른 체형의 뒷발이 지나치게 뒤에 남는 문제가 발견됐다. 회수 곡선의 큰 접선도 발을 약 11px 뒤로 끌어당겼다. 구성된 새 보행 경로에만 뒤쪽 도달 범위 6.75px와 착지 반보폭 6.5px 한도를 적용했다. 발을 직접 이동하거나 지지점에서 잘라내는 대신 정확한 접점에서 일찍 회수한다. 이륙·착지의 수평 속도 접선은 짧은 경계 구간에 두어 C1 연속성을 유지하면서 회수 중 과도한 뒤쪽 이동을 막았다. 시작된 곡선은 다음 이륙까지 같은 방식을 유지한다.

후속 검사 결과:

- 기존 기본 보행·적응 속보·고정 18px 보행의 3,600개 표본은 변경 전과 바이트 단위로 일치했다.
- 갤럽·전환 검사 110,529개 조건이 통과했다. 실제 지지점의 세계 좌표, 회수 범위, 모드 변경 직후 속도와 초기화 전 시작된 회수의 연속성을 검사한다.
- 실제 크림·실버 원본 PNG를 사용한 네 체형의 전환 검사에서 최대 관절 도달 오차 0px, 지지 발의 세계 좌표 오차 약 `1.14e-13px`를 확인했다.
- 정상 속도 검사에서 잘못된 알파 합성, 불투명 그림의 출력 경계 잘림과 바닥 아래 침범은 없었다.

이 수치는 Linux에서 실제 C++ 동작 선택기와 관절 렌더러를 실행한 결과다. Win32/GDI+ 출력이나 실행 중인 Box2D 창 환경의 기록은 아니다. Windows x64 실행과 ZIP·업데이트 피드·공개 파일 검증은 통합 검증에서 별도로 확인해야 한다. 전체 변경과 최종 증거는 [v2.0.9 기록](../V2_0_9.md)에 추가한다.
