# v2.0.33 근거리 포인터 왕복 진단

2026-11-13. 현재 실행 파일의 FileVersion/ProductVersion은2.0.33이다. 기존 동작 코드를 유지하고 진단용 진입점만 추가해, 실제 포인터 샘플 처리·모터·Box2D·표시 포즈·GDI+ 렌더러를 실행했다. 실행 중인 사용자 고양이와 프로필은 바꾸지 않았다.

## 재현

고양이 초기 위치400px을 중심으로 포인터만±48px, 초당1.5/3회 왕복시켰다. 높이는25/65/110px이며 입력은 고양이 움직임과 독립적이다. 세 외형 ×두 속도 ×세 높이,18개 경우를 각각20초·16ms 간격으로 실행했다. OS 포인터는 움직이지 않았다.

초당3회·높이110px에서는 세 외형 모두1250프레임 중1205프레임(96.4%,19.28초)을 달리기 턴에 사용했고, 실제 도약은0회였다. 크림냥의 높이65px 사례에서도901프레임(72.1%,14.42초)이 턴이었다.

크림냥·높이110px·초당3회 사례의 실제 전환 기록:

| 시간 | 동작 |
|---|---|
| 0.256초 | 포인터가 왼쪽으로 지나가자 점프 준비 그림으로 진입 |
| 0.368초 |112ms 만에 준비를 취소하고 달리기 턴 시작 |
| 4.944초 | 턴이 끝나 달리기 그림으로 복귀 |
| 4.960초 |16ms 뒤 반대 턴을 다시 시작 |
| 9.536초 | 달리기로 복귀 |
| 9.696초 | 다시 턴 시작 |

같은 높이65px 사례에는5.472초에서5.488초로 넘어가는16ms 사이에 같은 걷기0번 그림의 좌우 반전이 바뀌고, 다음 프레임에 턴0번 그림으로 전환되는 기록도 있다. 큰 달리기 방향 전환과 몸 바로 앞의 작은 왕복을 같은 방식으로 처리하고 있다.

## 코드에서 확인한 원인

1. `CursorReaction::Result`는 포인터가 몸 중심에서18px만 넘으면 추격 방향을 즉시 바꾼다. 근거리 왕복에 별도의 방향 유지 기준이 없다.
2. `PursuitAttempt`의 제자리 Reach 반응은 포인터 속도18px/s 이하이고450ms 동안 가만히 있을 때만 선택된다. 빠르게 움직이는 가까운 포인터는 이 경로를 벗어나 추격·도약 판단으로 들어간다.
3. `UpdatePrimaryGroundArt`는 추격 방향과 몸 방향이 다르면 실제 달리기 턴을 시작한다. 턴은 제동1000ms +회전1500ms +재출발2083ms, 합계4583ms다. 턴 중에는 새 공격을 차단한다.
4. `Turn::Motor`는 재출발 동안 처음 정한 방향으로 현재 요청 속도의 절댓값을 적용한다. 그사이 포인터가 반대로 움직여도 최초 방향으로 재출발할 수 있다. 끝나자마자 다시 반대 턴이 걸리는 이유다.
5. 점프 준비 도중 포인터가 뒤로20px 넘게 지나가면 즉시 Chase로 바뀐다. 현재 authored 그림 경로는 다른 포즈를 혼합하지 않고 바로 그리므로, 준비 그림·걷기·턴 사이의 갑작스러운 전환이 그대로 보인다.

턴의 긴 원본 영상이 근거리 손놀림에도 계속 선택되는 것이 확인된 핵심 문제다. 이번 재현에서는 매 틱 동작 시계 전체가 초기화되거나 영상 파일이 다시 디코딩되지는 않았다.

## 처리 시간과 측정 범위

18개 경우의 업데이트99백분위는 약0.04–0.06ms, 오프스크린 GDI+ 렌더링99백분위는2.01–5.71ms였다. 이 재현의16ms 프레임 간격보다 작다. 같은 원본 그림이 고정된 최장240ms는 최초 Watch 대기 구간이었다.

이 수치는 메모리 입력과 실제 그림 선택/렌더러를 측정한 값이다. 실제 Windows 메시지 큐·창 합성·모니터 출력의 프레임 간격까지 측정한 것은 아니므로 추가적인 데스크톱 지연을 배제하는 자료로 쓰지 않는다.

## 수정이 필요한 지점

몸 가까이에서 왕복하는 입력은 제자리 앞발·시선 반응으로 처리하고, 실제로 멀어지는 포인터의 추격과 구분해야 한다. 짧은 방향 변경은 목표로 확정하기 전에 지속성을 확인하고, 시작한 동작의 소유권·회복 시간을 유지해야 한다. 턴이 끝날 때에는 이전 목표 방향으로 다시 가속하는 문제도 함께 처리해야 한다.

이번 작업은 원인 진단이며 동작 선택 규칙과 배포 파일은 변경하지 않았다. 기존 드롭샷 원본·등록·캐릭터 원화도 그대로다. 진단은 `--cursor-jitter-diagnostic`으로 재실행할 수 있다. 결과는 `render-self-test/cursor-jitter/report.json`과 `trace.csv`에 기록한다.
