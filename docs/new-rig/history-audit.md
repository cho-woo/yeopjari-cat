# 기존 리깅 구현 검토와 새 제작에서 바꿀 점

이 문서는 과거 소스·검토 기록·보관된 GDI+ 이미지의 읽기 검토다. 과거 사용자 PC에서 모든 결함을 다시 실행 관찰했다는 뜻은 아니다. 확인된 구현 사실과 새 제작에서 피할 위험을 구분한다.

## 현재 원본과 활성 경로

현재 Walk는 `assets/care-sprites/c0-walk.png`의 앞8셀이다. 공통 기준점은 `(161,275)`, `referenceHeight=221`이다. 실제 프레임 rect는313/314px여서 bbox에 맞춰 매번 크기를 바꾸면 안 된다. `DrawStyledAnimationDirect`가 먼저 `DrawCareSprite`를 호출하고, 등록된 원화가 있으면 반환하므로, 남아 있는 예전 `cat_articulated_walk.hpp`/`cat_locomotion_rig.hpp` 코드를 현재 크림치즈냥의 기본 걷기라고 해석하면 안 된다.

v2.0.17 검토에서 생성한48/64/16셀은 승인0장이고 제품 원화를 대체하지 않았다. `docs/walk-art-review/README.md`의 접지·높이·원본 연결 실패 기록을 새 리그 제작의 기준으로 사용한다.

## 과거 구현에서 확인한 사실

### v2.0.14 부품 리그 — 이미 IK와 메시를 사용했다

[추가 커밋5b863d4](https://github.com/cho-woo/yeopjari-cat/commit/5b863d4239452b7dc4d0939d29c8e8071baddee8)의 삭제된 `src/cat_cream_rig.hpp`는 두 뼈 IK와9×16 메시 격자를 사용했다. 따라서 새 제작을 ‘이번에 처음 IK/메시를 도입한다’고 설명하면 정확하지 않다.

구현의 구체적인 제약은 다음과 같다.

- `PrepareParts`29–36행은 생성된 부품마다 알파bbox를 따로 구하고 **각 bbox를256×256으로 독립 리샘플링**했다. 조립 단계는 머리150×166, 몸통137×74 등의 별도 하드코딩 크기를 사용했다(45–54행). 원본 고양이의 공통 픽셀 배치·비율을 그대로 보존하는 작업 파일이 아니었다.
- 5개 텍스처(머리·몸통·앞다리·꼬리·뒷다리)만 있었다. 가까운/먼 앞다리와 가까운/먼 뒷다리가 각각 같은 그림을 공유하고 먼 다리는 tint=.89로 표시됐다(101–107,143–144행). 네 다리의 가려진 관절·털 연결을 개별적으로 편집할 원화는 없었다.
- IK의 관절점·뼈 길이·body/sit 변형은 C++ 상수였다. `Bone`94–99행은 목표 뼈 길이에 따라 텍스처의 길이 방향을 늘였고, 뒷다리는120–125행에서 세로 매핑을 압축했다. 현재 원본의 다리 길이·두께를 보존했는지는 숫자 발 목표만으로 증명되지 않는다.
- 모델 원본은 PNG와 C++이었다. 메시 토폴로지·가중치·가림·교정 형태를 재편집하는 `.blend`/레이어 작업 파일은 커밋에 없었다.
- `tests/cat_cream_motion_test.cpp`는 접지 목표의 세계 좌표, 알파, 출력 버퍼 등을 검사했지만, 마지막 raster 검사는 단색 부품fixture도 사용했다. 실제 털 이음새나 원본 얼굴·몸통 비율의 동일성을 입증하는 검사는 아니었다.

보관된 `docs/media/cream-walk-stand-sit-gdi.png`를 현재 `docs/walk-art-review/original8-normalized-reference.png`와 비교하면 다리·몸통 비율과 얼굴/몸 연결이 현재 원본과 다르게 보인다. 다만 각 코드 선택이 사용자의 제거 요청에 얼마나 기여했는지를 확정한 독립 실험은 없다.

[복원 커밋5740458](https://github.com/cho-woo/yeopjari-cat/commit/5740458c3a09e1cee3a627aee930861e27e2c667)에서 리그 코드·부품 이미지·출발 전 대기를 제거했다. `docs/TWO_CATS.md:3`에 v2.0.13의 재생 경로로 복원한 범위가 명시돼 있다. 이번 작업은 그 삭제 코드를 다시 켜는 작업이 아니다.

### 더 오래된 마스크·inverse warp 리그

`docs/validation/v2.0.7-quadruped-audit.md`에는 당시 실제 이미지의 삼각형 빈 영역, 원본보다 과하게 뻗는 다리, 가까운/먼 뒷다리의 잘못된 서로 다른 무릎 방향이 기록돼 있다. 이 문서는 ‘발 좌표 검사만으로 합성 결함은 잡히지 않는다’고 명시한다.

현재 보관 코드에서도 원인을 읽을 수 있다.

- `src/cat_locomotion_rig.hpp:209` 이하: torso/leg 경계가 원본 픽셀의 해부학적 분리가 아니라 정규화 곡선 마스크다. 주석은 과거의 넓은 가슴 조각·먼 발가락의 절단·사각형 다리 문제를 설명한다.
- `src/cat_articulated_walk.hpp:39` 이하: 가려진 배 원화가 부족한 곳은 위쪽 같은 털 열의 픽셀로 채웠다. 실제 가려진 피부/털 방향을 작화한 부품과 다르다.
- `src/cat_articulated_walk.hpp:56` 이하: 실제로는 두 다리 텍스처를 마스크로 추출하고 네 다리로 재사용했다. 발 sole의 알파 측정과 reach 검사를 개선했지만, 독립된 네 팔다리 원본은 아니었다.
- 같은 파일의 `DrawLeg`는 도달 범위를 넘으면 목표 발목을 clamp한다. 수치 검수에서 clamped/reach error를 반드시 노출해야 하며, 새 제작에서는 이를 조용히 정상 접지로 처리하면 안 된다.
- `docs/validation/walk-run-dynamics-audit.md`는 고정된 상체68% 복사가 어깨·골반 무게 이동을 억제한 문제를 설명한다. 반대로 전신을 함께 위아래로 옮기면 고정 발까지 움직일 수 있으므로, 새 리그의 무게 이동과 세계 접지는 따로 제어해야 한다.

## 새 편집 원본에서 필요한 차이

1. **공통 캔버스·UV·원본 픽셀 보존:** 머리·얼굴은 현재 승인된 원본의 같은 픽셀을 사용하고, 모든 부품을 같은 원본 좌표에서 등록한다. 부품마다 tight bbox 정규화한 뒤 조립하지 않는다. 중립 조립을 원본과 겹쳐 크기·눈·귀·가슴·꼬리 위치부터 검수한다.
2. **독립된 네 다리와 목적 작화:** 가까운/먼 앞·뒷다리, 발바닥/발등, 가려진 어깨·겨드랑이·허벅지·배·꼬리 뿌리의 그림을 따로 보관한다. 새로 필요한 부분만 원화 보완한다. 마스크 경계 바깥의 불완전한 그림을 회전해 빈틈을 노출시키지 않는다.
3. **편집 가능한 메시와 교정:** Blender의 각 부품 메시·UV·스킨 가중치·관절 제어기·올바른 bend 방향을 저장한다. 발은 단단하게 보존하고 위/아래 다리와 연결부만 변형한다. 두께·면적이 과하게 줄거나 관절 털이 접히는 구간에는 명시적 교정 형태를 넣는다. 토폴로지는 그림 경계·관절을 따라 배치하며 오래된 고정 사각 격자 공식을 그대로 쓰지 않는다.
4. **도달 가능한 동작을 먼저 설계:** 중립 상태에서 뼈 길이와 굽힘 여유를 측정하고, stance 전체에서 hip/shoulder→paw 도달 범위를 확인한다. 도달 불가를 발 이동·뼈 늘림으로 숨기지 않는다. 목표를 바꿀 경우 보폭/접지 계획을 바꾼 사실을 기록한다.
5. **그림에서 보이는 실제 발까지 검증:** 리그의 네 발 ID·sole 제어점·접지 상태·세계 좌표를 직접 내보낸다. 발 제어기의 수치 고정에 더해 렌더된 sole/알파가 그 목표를 따르는지, 발 모양·그림 이음새가 자연스러운지 확인한다.
6. **짧은 contact study를 먼저:** 몸이 이동하는 동안 한 발을 world-lock하고 다른 발을 회수하는 클립으로 다리 길이·두께·연결부를 검사한다. 110논리px 실제 크기와22px/s 재생으로 원본 옆에 보여준다. 확대/본선 영상은 별도다. 이 클립의 결함을 해결하기 전 한 주기 완료로 보지 않는다.
7. **의도한 주기 운동과 jitter 분리:** 머리는 같은 강체 픽셀을 유지하되 몸통의 작은 주기 운동에 자연스럽게 반응하게 한다. 기획한 head/body curve와 출력 잔차를 따로 검증하고, 주기 운동의 진폭을 jitter 허용치로 넓히지 않는다. 원본 얼굴을 늘이거나 서로 다른 얼굴을 섞지 않는다.
8. **제작과 실행 분리:** `.blend`+원본 레이어/PNG+JSON+제작 스크립트로 오프라인 bake를 재현한다. Windows 앱은 그 결과 시퀀스를 기존 실제 렌더 경로로 검수한다. 실시간 리깅을 무작정 제품에 다시 넣어 저장·물리·CPU 경로를 확대하지 않는다.

## 검수 승인과 인수 자료

- 수치 승인: stance world-slip, reach error/clamp 횟수, 뼈 길이·두께, root/landmark 잔차, 마지막→처음의 위치/속도 연속성, 프레임 간 최대 root 이동량.
- 시각 승인: 본선 없는 실제110px/22px/s의 최소3주기, 원본과 나란한 외형·털 경계·관절 연결·부유감·반복 연결 확인. 수치 통과와 별도 상태로 기록한다.
- 프레임 수는 새 보폭과 실제 가장 큰 간격에서 산출한다. 64px 보폭에 root 간격≤1px이면 wrap 포함 최소64구간이며, 변형 속도가 빠른 구간 때문에 더 많은 표본이 필요할 수 있다.
- 넘겨줄 원본: 부품별 투명 PNG(같은 캔버스 좌표), 레이어/부위별 명칭, UV와 메시/가중치, 네 발 sole/pole 제어점, 고정 카메라·바닥·root, 동작 곡선·보폭, bake/contacts/report 스크립트, `.blend`에서 바로 열어 수정·출력하는 절차.
