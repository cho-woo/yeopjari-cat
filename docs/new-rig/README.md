# 편집 가능한 크림치즈냥 메시 보행 연구 — 시각 검수 불합격

**자연스러운 걷기 한 주기 완성은 아직 못했다.** 실제로 열고 수정할 수 있는 Blender 원본, 목적 작화한 숨은 부품, 발 제어·접지 데이터, 짧은 접지 클립과 미승인 비교 자료를 제공한다. 배·다리 가림 순서와 일부 사각 발 연결부는 개선했지만, 관절의 메시/UV 접힘과 원본 털의 연결이 자연스럽지 않다. 수치 검사를 통과시켜 이를 완성 원화로 취급하지 않는다. 기본 제품 보행은 기존 승인8장을 유지한다.

## 확인한 원본과 과거 실패

현재 제품은 C++17·Win32 투명 레이어 창·GDI+·Box2D를 사용한다. Walk는 `assets/care-sprites/c0-walk.png`의 앞8셀, 공통 기준점 `(161,275)`, 기준 높이221이다. 기존 보폭64논리px와 거리 비중 `[75,75,75,202,342,75,81,75]/1000`은 일반 실행에서 유지한다. 실제 지상 이동거리→보행 위상, 고정1/60초 물리, 표시 위치 보간, v2.0.17의 공통 정지 대기는 재사용한다.

[과거 구현 감사](history-audit.md)는 기존 IK/메시 코드의 부품별 독립 bbox 확대, 공유 다리 텍스처, 가려진 원화 부족, 관절 방향, 숫자 검사와 실제 그림의 불일치를 구분한다. 이번에는 삭제된 런타임 리그를 복원하지 않았다. Blender에서 공통313² 좌표·고정 카메라·원본 머리 픽셀·독립 네 다리·목적 작화한 숨은 부품을 편집하고, Windows 앱에는 오프라인 PNG bake만 넣는다.

## 실제 제작 범위

- 머리·상체 외곽·꼬리·가까운 발은 승인된 원본 픽셀을 사용한다. 프레임 bbox별 확대·축소나 완성 그림 사이 페이드는 사용하지 않는다.
- 이미지 도구로 **6개 부품 셀**을 한 번 목적 작화했다. 숨은 몸통과 가까운/먼 앞·뒷다리의5셀이 사용된다. 여분 꼬리 뿌리 셀은 원본 대체에 사용하지 않았다. 전체 걷기 시트를 다시 생성하지 않았다.
- 네 발의 sole 제어기와 고정 길이 두 링크 IK, 강체 발가락, 다중 가중치 메시, 독립 머리·몸통·꼬리 메시가 있다. `.blend`에 원화·UV·가중치·키프레임을 보관한다.
- 보폭은 이 리그의 실제 도달 범위1024위상 검사에서 산출했다. 현재 선택30논리px, 22논리px/s에서1.3636초/주기다. 기존64px는 이 리그의 고정 다리 길이를 초과한다.
- 네 발의 위상: 가까운 뒷발0, 가까운 앞발0.25, 먼 뒷발0.5, 먼 앞발0.75. 각 발은 주기의64%를 접지하고36%를 회수한다. 회수 높이4.4논리px, 접지 중 상대 발 속도는 몸의 전진 속도와 반대다.
- 프레임 수는 먼저 정하지 않았다. `ceil(max(보폭/1px, 주기초×60원본표본/초))=82`로 산출했다. **82개는 메시를 다른 자세로 렌더한 표본 수**이고, 독립적으로 손으로 그린 새 보행 원화82장이 아니다. 중립 측면 서기는 반복에 포함되지 않는 별도1자세다.
- 머리·몸통의 작은 주기 운동은 리그에 선언한 저차 Fourier 곡선과 비교한다. 그 잔여 떨림을 검사하며, 발 미끄러짐 허용치를 넓히지 않았다.

## 짧은 접지 클립에서 확인한 실패

1차는 몸통이 가까운 다리의 연속 메시를 가리고 배를 수평으로 잘랐다. 2차는 깊이 순서·가슴 연결·뒷다리 굽힘 방향과 먼 앞발 원화를 고쳤다. 3차는 가려진 원본에서 추출한 먼 뒷발의 사각 캡을 완전히 그려진 새 발로 바꾸고 관절 가중치를 넓혔다.

여전히 앞다리 관절의 수평 털 이음새, 뒷허벅지/발목의 평평한 돌출부, 어깨·엉덩이의 붙인 듯한 색/털 경계가 보인다. 고정 뼈 길이와 발 목표 오차가 작아도, 메시 삼각형의 길이 방향 압축·확대가 크다. 링의 가로폭이 유지된다는 검사만으로 표면이 자연스럽다고 판단할 수 없다. 이 때문에 짧은 클립은 시각 검수 불합격이다.

완전한 주기 렌더와 앱 검토본이 포함되더라도 **같은 실패 원본을 검사·인수하기 위한 미승인 진단 자료**다. 짧은 클립을 통과한 완성 보행으로 보고하지 않는다.

## 편집과 재출력

원본은 `assets/cream-mesh-source/authoring.blend`, 원화 출처는 같은 폴더의 `source-provenance.json`이다. 세부 조작과 재출력은 `tools/cream_mesh_rig/README.md`를 따른다. Blender4.3.2를 사용했다. 일반 Python 도구에는 Pillow·numpy, 영상 출력에는 FFmpeg가 필요하다.

```bash
# 새로 구성: 기존 수동 편집을 보존하는 경로가 아니므로 의도적으로만 사용
blender -b --python tools/cream_mesh_rig/author.py -- --mode short --output build/cream-mesh-rig

# 수정한 .blend의 메시·UV·가중치·키를 그대로 사용해 재출력
blender -b edited.blend --python tools/cream_mesh_rig/author.py -- --existing-blend edited.blend --mode bake --output build/edited-mesh
python3 tools/cream_mesh_rig/pack.py build/edited-mesh
python3 tools/calibrate_walk_contacts.py build/edited-mesh/annotations.json --output build/edited-mesh/calibrated-manifest.json --report build/edited-mesh/calibration-report.json
python3 tools/cream_mesh_rig/assemble_review.py build/edited-mesh
python3 tools/import_mesh_walk_review.py --manifest build/edited-mesh/review-manifest.json --annotations build/edited-mesh/annotations.json
```

의도적으로 몸통 곡선을 변경했다면 리그의 `motion_contract_json`도 명시적으로 갱신해야 한다. 오차에 맞춰 곡선을 임의 피팅하거나 허용치를 높이지 않는다. 루프82장과 중립83번째 자세는 따로 취급한다. `assemble_review.py`는 실제 PNG 해시와 루프의 사각형·기준점·단독 중립 자세를 검사하고, 보정된 거리 비중과 보폭을 그대로 보존한 별도 검토 매니페스트를 만든다. 프레임 수는 입력에서 읽으며, 중립 자세를 루프에 넣거나 균등 재생 비중으로 대체하지 않는다. 보정·조립이 성공한 뒤에만 앱에 등록한다.

```bash
bash tools/check.sh
```

편집 원본 ZIP만 풀었을 때도 `.blend` 열기와 재출력은 가능하다. 전체 Windows 앱 재빌드는 같은 커밋의 `cho-woo/yeopjari-cat` 전체 저장소와 고정 llvm-mingw/Box2D가 필요하다.

## 다음 제작자가 필요한 작업

- `near_front.continuous_fur`, `near_rear.continuous_fur`의 관절 내부와 발목 링: 구부릴 때 접히는 토폴로지·UV를 다시 잡고, 피부 면적/길이 왜곡을 줄이는 교정 shape key를 만든다. 발 sole와 고정 뼈 길이는 유지한다.
- 가까운/먼 어깨·겨드랑이, 양쪽 엉덩이·서혜부, 네 발목 윗부분의 **가려진 연결 원화**를 현재 캐릭터의 털 방향·색·두께에 맞춰 수정한다. 특히 전방 회수·최대 후방 접지·발을 드는 순간의 연결을 확인한다.
- 필요한 형식:313×313 공통 캔버스의 부위별 RGBA PNG와 레이어 이름을 유지한 `.kra`/`.psd`, 또는 기존 packed texture를 교정한 `.blend`. 기준점 `(161,275)`, 높이221, X오른쪽/Z위쪽의 현재 리그 좌표를 유지한다. 부품별 tight bbox 재정규화는 하지 않는다.
- 교정 shape key는 위상/관절 각도에 대응하는 드라이버 또는 명시적 키로 저장하고, 중립·최대 전방 회수·최대 후방 접지·상승/하강의 두께와 털 이음새를 검수한다.
- 짧은 접지 클립이 본선 없는 실제110px/22px/s에서 자연스러워진 후, 같은 원본으로 주기 전체를 재출력하고 마지막→첫 프레임을 다시 본다. 그 다음에 출발·발 회수 후 정지·회전·앉기 연결 원화를 진행한다. 현재 중립 측면 서기1장은 전용 연결 애니메이션이 아니다.

## 앱에서 확인

기존 고양이를 알림 영역 우클릭→종료로 닫고, 검토용 ZIP을 완전히 푼 뒤 `Launch-Mesh-Walk-Review.cmd`를 실행한다. 일반 `YeopjariCat.exe` 실행은 기존8장을 유지한다. 검토 모드는 크림치즈냥·턱시도냥에 같은 보행 등록과 보폭을 적용하며, 턱시도는 기존 캐시 털색 변환을 사용한다.

`YeopjariCat.exe --render-mesh-walk-review`는 실제 GDI+ `DrawCareSprite`와 Box2D로 비교 PNG를 출력한다. 이것은 실제 앱의 렌더링 경로를 사용한 진단 출력이며, 바탕화면을 녹화한 영상은 아니다. 활성 앱 갱신은16ms 목표, 물리는60Hz, 비교 영상은60FPS다. 접지 확대 영상은60Hz 표본을20FPS로 인코딩한3배 감속이다.

검증 출처·최종 수치·영상 파일은 후속 `validation.json`과 각 영상 proof에 기록한다. 수치 통과와 시각 불합격은 별도로 유지한다.

## v2.0.19 진단 보정

v2.0.18의 새 비교 진단에서는 턱시도 표시 배율 `110 / standingHeight`가 정수 나눗셈으로0이 되어 오른쪽 캐릭터가 비었다. 일반 앱의 공유 털색 경로와 기존 두 캐릭터 GDI+ 검사는 정상으로 확인했다. v2.0.19는 `110.0`으로 수정하고, 매 비교 프레임에서 두 행·두 캐릭터의 실제 색 픽셀 수를 검사한다. 두 영역이 모두 비어 있어도 같은 알파라는 이유만으로 통과하는 것을 막는다. 이 수정은 원화의 시각 검수 불합격 상태를 바꾸지 않는다.
