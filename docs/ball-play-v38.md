# 공놀이 접촉 및 연속성 검토 (2.0.38)

## 원인과 변경

기존 공놀이는 6.583초 영상에 넓은 시간 창과 한 번의 타격을 붙였다. 특히 턱시도의 접촉 표식은 실제로 뻗는 앞발보다 안쪽의 낮은 털에 붙었다. 공이 떠난 뒤에도 같은 영화의 앞발 동작이 이어졌다. 접근 뒤 정면으로 돌아오는 걷기 종료와 옆모습의 공놀이 진입도 맞지 않았다.

수정 전 기본 60초 장면에서 물리 좌표의 순간이동은 검출되지 않았다. 보이는 튐을 모두 물리 순간이동으로 단정하지 않는다. 등록 기준점, 자세 전환, 공 표시 범위를 함께 점검했다. 동반 고양이는 공 범위를 자신의 x±95로 매번 바꾸고, 공을 자신의 작은 창 안에 그렸다. 공을 쫓는 동안 좌표가 잘리거나 표시가 사라질 수 있는 구조였다.

드롭샷에 같은 원화의 시작·끝 참조를 넣어 낮은 단일 타격 두 편을 생성했다. 요청 프롬프트보다 실제 동작이 느리게 생성되어, 실제 원본의 24fps·97프레임·4.042초 전체를 유지했다. 원본, 생성 응답, 교체 전 등록 정보는 assets/video-actions/{sources,selected}/ball-v38에 보존한다. 고정 가로 기준점 480, 기록된 바닥 686/688, 공통 367 높이 기준을 사용한다. 자세별 확대나 회복 생략은 하지 않는다.

움직이는 발끝을 주석 처리하고 최종 투명 스프라이트의 실제 털 픽셀에 맞춘다. 같은 화면 좌표계의 보간된 몸·발·공을 사용해 이동 구간과 원의 충돌을 검사한다. 타격 시간 창, 접근 속도, 방향 조건과 실제 겹침이 모두 필요하다. 한 동작당 충돌은 한 번이며, 빗나감·발 회수·공중 상태에는 힘을 주지 않는다. 실제 발 속도와 접촉 면의 법선·접선으로 이동과 회전을 계산한다. 힘을 줄 때 보간 위치를 초기화하지 않는다.

공의 접근 제어와 일반 배회의 가장자리 12픽셀 제동이 충돌하던 정지도 발견했다. 공놀이는 자신의 제한된 목표 위치 제어를 사용하고, 도달할 수 없는 쪽은 반대편에서 접근한다. 접근·주시·타격·발 내려놓기·추적·실제 회전·휴식의 소유권과 시계를 유지한다. 자동 행동이 도중에 재시작하지 않는다. 동반 고양이도 네 번의 완전한 놀이와 휴식까지 수행하며, 공은 화면 좌표의 독립적인 클릭 통과 레이어에 표시한다. 그림자는 바닥에 남는다.

## 검증 경로

- `--ball-review 외형ID 동반여부`: 60초, 60Hz의 실제 실행 파일 물리·행동·GDI+ 렌더 경로를 30fps PNG와 CSV로 내보낸다. 외형 ID는 0/8/10, 동반 여부는 0/1이다.
- `--ball-review-all`: 3외형 × 2동물 × 8조건 = 48개 장면을 각각 60초 검사한다. 기본 배치, 가까운 공, 먼 공, 빠른 복귀, 가장자리 왕복, 창 지지와 제거, 150% 배율·음수 화면 원점, 어린 성장 크기를 포함한다. 월드 좌표 재배치는 초기 배치에서만 허용한다. 창 제거는 실제 중력으로 착지한다.
- 동일한 드롭샷 원본 전체와 같은 캐릭터 디자인, 발끝 알파, 고정 등록점, 공통 크기를 자동 검사한다.
- 별도 Win32 레이어 검사에서 100%/150% 배율, 음수 화면 위치, 고양이의 x·높이 변화, 공 높이, 바닥 그림자, 숨김을 실제 창과 픽셀로 검사한다.
- 기존 Windows 자기 검사, 공 물리·접촉·동반 고양이 회귀 검사 및 기존 공놀이 캡처도 유지한다. 약한 타격을 매번 벽에 부딪히게 강제하지 않고, 반사는 가장자리·복귀 조건에서 별도로 검증한다.

영상은 생성한 시연이 아니라 해당 EXE의 실제 렌더 출력이다. 전체 바탕화면의 화면 녹화는 아니다. 고정 카메라의 공과 고양이를 함께 보여 주며, 정상 속도와 접촉·회전·회복의 0.25배 재생을 보관한다. 배포 전 CI 산출 EXE의 SHA-256을 기록하고, 그 파일로 다시 검사한 뒤 같은 파일만 배포한다.

공은 바닥 장난감이다. 창 위나 공중에서는 허공 타격을 하지 않으며, 바닥에 돌아온 뒤 접근을 재개한다. 성장·먹이·계정 기록을 이 검사에서 읽거나 저장하지 않는다.
