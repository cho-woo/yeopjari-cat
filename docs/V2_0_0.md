# v2.0.0 — 오래 함께하는 두 마리

v1.10.3의 저장 호환성과 자동 업데이트를 이어서, 친밀도·생활 상태·창과 커서 상호작용·의상·장난감·두 동물 육성을 묶은 버전입니다. Windows 10/11 x64가 대상이며 물리엔진은 Box2D 3.1.1을 유지합니다.

이 문서는 구현 범위와 배포 전 검증 상태를 구분합니다. 현재 Windows 네이티브 CI 및 공개 배포 검증은 완료 결과를 기다리는 단계입니다. 배포 완료를 뜻하는 문서가 아닙니다.

## 1단계: 구현과 저장 호환성

### 함께한 시간과 돌봄 기억

- 실제 생일과 밥·츄르 기록, 성장·체형·친밀도·취향을 이어갑니다. 10년을 지났다는 이유로 죽거나 초기화되지 않습니다.
- 쓰다듬기·놀아주기·식사 경험에 따라 친밀도와 선호가 쌓입니다. 반복 클릭에는 시간 간격과 하루 인정량 제한이 있으며, 사용하지 않은 기간을 새로운 돌봄으로 계산하지 않습니다.
- 기존 동물의 생일에서 파생한 기본 성격은 유지합니다. 돌봄에 따른 학습 보정은 작고 느리게 누적됩니다.
- 새로 만나는 동물은 겁쟁이·개냥이·시크냥·먹보·장난꾸러기·잠보 중 고정된 초기 성향을 갖습니다. 외형을 바꿔도 생일과 기억을 다시 만들지 않습니다.
- 졸림·심심함·기분·활동 상태는 행동 선택에 반영합니다. 숨김·정지·긴 오프라인 구간을 감정 변화로 한꺼번에 재생하지 않습니다.
- 아침 기지개, 점심의 식사 요청, 오후 활동과 밤 수면, 가끔 새벽 우다다를 유지합니다. 식사·간식 요청은 기존 포만감과 요청 간격 제한을 함께 따릅니다.
- 오래 함께한 행동은 기간과 친밀도를 함께 요구합니다. 90일·친밀도 25부터 오랜 친구의 꾹꾹이, 실제 1주년·45부터 인사 시퀀스, 실제 5주년·65부터 장기 유대 시퀀스가 후보가 됩니다. 조건을 만족한 날에 반드시 실행되는 보상은 아닙니다.

### 실제 창과 커서의 거리

창 사이 점프는 출발 위치·높이, 목표 창의 윗면·착지 공간, 중력과 감속 거리를 확인합니다. 높은 창은 살펴보고, 도달하지 못하는 창에는 가짜 도약을 시작하지 않습니다. 이동·크기 변경 중인 창은 실제 지지면으로 갱신하고, 닫힌 창은 제거한 뒤 남아 있는 속도로 내려옵니다.

드문 창 끝 매달리기는 Box2D의 감쇠된 거리 제약으로 지지면에 붙었다가 힘을 받아 올라오거나 중력으로 내려옵니다. 일반 창 이동과 매달리기에서 순간이동으로 착지를 대신하지 않습니다. 화면 반대편에 나타나는 행동은 별도로 제한되는 의도적인 희귀 연출입니다.

‘업무 방해 모드 · 커서와 놀기’는 기본 OFF입니다. ON일 때 커서를 관찰·추적하고 냄새를 맡거나 앞발로 장난칩니다. 너무 빠르거나 먼 커서는 포기합니다. 멈춘 낮은 커서에는 드물게 실제로 다가가 잠깐 앉으며, 커서 이동이나 옵션 해제로 끝납니다. 포인터를 이동하거나 운영체제 입력을 만들어 내지 않습니다.

이 모드를 꺼도 기존 작업표시줄 산책과 일반 창 위 걷기는 유지됩니다. 자동 이동까지 멈추려면 ‘이 자리에서 쉬기’를 선택합니다. 창 위의 몸은 클릭할 수 있고, 지지하는 프로그램의 영역은 클릭을 통과시킵니다.

### 10종 캐릭터, 옷장과 여섯 장난감

| 구분 | 선택 항목 |
| --- | --- |
| 고양이 8종 | 크림 치즈냥, 실버 태비냥, 까만냥, 삼색냥, 샴냥, 먼치킨냥, 턱시도냥, 브리티시냥 |
| 다른 동물 2종 | 옆자리 멍멍이, 옆자리 토끼 |
| 옷장 13항목 | 미착용, 빨간 리본, 목도리, 왕관, 산타 모자, 붕어빵 모자, 회사원 넥타이, 포근한 후드티, 선글라스, 상어 옷, 공룡 옷, 호박 모자, 생일 모자 |

캐릭터는 각자의 그림을 사용하며 이동 속도·도약 높이·먹이 관심·말 걸기·커서 관심에 작은 차이를 둡니다. 먼치킨의 낮은 도약 한계도 실제 목표 창 도달 검사에 적용됩니다. 의상은 자세·좌우 반전·체형과 얼굴·목 위치를 따라갑니다. 옷장 13항목에는 ‘미착용’이 포함됩니다.

장난감은 발견·접근·살펴보기·접촉·휴식·이탈을 이어가는 짧은 행동 흐름을 사용합니다. 공은 실제 Box2D 동적 원으로 굴러가고 앞발 접촉 시점에 힘을 받으며 벽·바닥과 충돌합니다. 박스·종이봉투에 들어가 쉬기, 캣닢 곁에서 뒹굴기, 낚싯대 앞발 놀이, 쿠션에서 꾹꾹이와 수면을 할 수 있습니다. 장난감은 창 위로 따라 뜨지 않고 작업표시줄 바닥에 남습니다. `Ctrl+Alt+B`로 박스를 꺼낼 수 있습니다.

### 수면, 얼굴과 희귀 행동

수면은 웅크리기·옆으로 눕기·식빵잠·배 보이고 자기·앞발에 얼굴 묻기·꼬리로 얼굴 가리기의 여섯 자세를 사용합니다. 창 위에서는 앉은 채 졸며 고개를 떨굽니다. 강아지와 토끼의 얼굴 가리기는 귀·앞발 형태에 맞춘 그림을 사용합니다. 표정은 기존 얼굴의 눈·입 위치를 기준으로 변화하며, 몸 회전 중 별개의 얼굴을 덧그려 겹치지 않도록 합니다.

이동·점프·공 충돌·매달리기는 Box2D로 계산하고, 그림의 귀·머리·발과 얼굴은 2D 관절 및 국소 변형으로 표시합니다. 배 까기는 한 개의 머리를 연결해 크기 변화와 중복 얼굴을 막으며, 몸통 자세를 바꾸는 180ms 구간에는 짧은 그림 혼합이 남습니다. 전신의 모든 관절을 물리로 계산하는 리그와는 검증 범위를 구분합니다.

펀치·재채기·꼬리 놀이 후 본인이 놀라기, 잠꼬대, 작은 박스, 왕관 자세, 창 끝 매달리기, 화면 반대편 등장과 오랜 유대 시퀀스는 특별 행동 후보입니다. 기본 걷기·재채기·냥냥펀치 자체와 특별 후속 연출을 구분합니다.

특별 행동은 동물과 날짜에서 정한 하루 0~2회 기회, 최근 24시간 최대 2회, 최소 4시간 간격을 함께 적용합니다. 재시작해도 기록을 유지하고, 기존 기억의 희귀 행동 시각도 새 생활 기록에 이어받습니다. 메뉴·먹기·점프·다른 상호작용 중에는 새 특별 행동을 끼워 넣지 않습니다.

계절 옵션은 기본 ON이며 별도로 끌 수 있습니다. PC의 날짜로 크리스마스·할로윈·생일 모자, 겨울 목도리 추천, 함께한 1주·1년·5년 기념 반응을 제공합니다. 이미 착용한 의상은 옵션 변경으로 벗기지 않습니다. 외부 날씨·위치 API와 실제 비 오는 날 연동은 이번 버전에 포함하지 않습니다.

### 두 번째 동물

‘두 마리 함께 키우기’에서 사용자가 선택한 뒤에만 두 번째 동물을 만듭니다. 별도의 투명 창, Box2D 몸체와 행동 선택기를 사용하며 기존 메인 타이머에서 함께 갱신합니다. 첫 번째 동물의 전역 상태를 임시로 바꿔 그리는 방식은 사용하지 않습니다.

두 동물의 생일·성장·포만감·체형·성격·친밀도·돌봄·외형을 독립적으로 저장합니다. 냄새 맡기, 따라 걷기, 함께 뛰기, 앞발 장난, 나란히 자기, 먹이 곁으로 다가가기, 다른 동물을 따라 창에 오르기가 있습니다. 고양이끼리 노는 것으로 사용자 돌봄 횟수나 실제 먹지 않은 먹이를 기록하지 않습니다. 공중에서의 먹이·쓰다듬기는 착지할 때까지 받지 않습니다.

두 번째 동물은 직접 우클릭해 밥·간식·외형·휴식·성장 기록을 선택합니다. `Ctrl+Alt+F/T`는 기존처럼 첫 번째 동물용입니다. 두 번째 동물 표시를 꺼도 기록을 삭제하지 않습니다. 서로의 저장 파일을 덮어쓰지 않으며, 두 번째 동물의 손상된 기록을 새 생일로 바꾸어 재생성하지 않습니다.

두 번째 동물에도 시간대별 행동 비중·기분 상태·계절 의상 해금이 적용되며, 특별 희귀 시퀀스·기념일 반응·식사 요청 말풍선은 첫 번째 동물에게 적용됩니다.

### 저장 파일과 자동 초기화

사용자 폴더는 계속 `%LOCALAPPDATA%\YeopjariCat`입니다.

| 기록 | 파일과 호환성 |
| --- | --- |
| 첫 번째 동물의 생일·성장·돌봄 | 기존 `pet.ini`, `pet.bak`, 월별 파일; 기존 schema 1 유지 |
| 첫 번째 동물의 체형·식사 | 기존 `nutrition.ini`, `nutrition.bak`; 기존 복구 규칙 유지 |
| 친밀도·취향·느린 학습 | 기존 `memory.ini`, `memory.bak`; 기존 schema 1 및 생일 소유권 유지 |
| 기존 캐릭터·의상 | `preferences.ini`, `preferences.bak`; schema 1/2 읽기 유지, 기존 키를 보존하고 선택지만 확장 |
| 새 생활 상태 | `life.ini`, `life.bak`; 기존 생일로 자동 초기화, 기존 성격은 유지 |
| 두 번째 동물 | `companion.ini`, `companion.bak`; 별도 생일을 가진 성장·영양·기억·생활·외형을 검증된 한 묶음으로 저장 |
| 커서·계절 옵션 | `interaction-settings.ini`와 백업; 커서 놀이 기본 OFF, 계절 기본 ON |
| 소리·업데이트 | 기존 `sound-settings.ini`와 백업, `update-settings.ini`, `update-notice.ini` 유지 |

새 생활 기록은 기존 고양이에게 가상의 과거 감정이나 돌봄을 만들어 주지 않습니다. 기존 저장 데이터를 사용자가 편집하거나 수동으로 변환할 필요는 없습니다. 추가 기록에는 체크섬·생일 일치·임시 파일 재읽기·원자적 교체·백업·손상 원본 보존을 적용합니다. 다른 세션이 바꾼 파일을 덮어쓰지 않습니다.

메뉴의 ‘성장 기록 따로 백업하기…’는 기존 첫 번째 동물의 성장 파일만 내보냅니다. **두 동물의 기억과 모든 설정을 옮기려면 앱을 종료하고 사용자 폴더 전체를 복사해야 합니다.** EXE와 ZIP만 옮기거나 성장 파일 하나만 내보내는 것으로 전체 기록이 복원되지는 않습니다.

### 소리 교체 범위

현재 효과음은 첫 번째로 제공받은 영상의 `b`(2.12–2.63초), `c`(2.68–3.22초), `d`(4.00–4.74초)를 14개 행동 슬롯에 나눠 사용합니다. 사용자가 제외를 요청한 첫 구간 `a`(0.18–0.91초)는 모든 슬롯에서 제외합니다. 영상 끝에서 잘린 구간도 사용하지 않습니다. 배 까고 뒹굴기는 재생 중인 소리와 대기 중인 소리를 멈추고 조용히 진행합니다.

피치·재생 속도·자연스러운 길이를 바꾸지 않고, 모노 22.05kHz PCM16 변환·DC 제거·음량·시작과 끝 페이드만 적용합니다. 음소거·음량·자동 재생 간격·겹침 방지와 기존 리소스 ID 301–314를 유지합니다. 서로 다른 원본 소리 14개를 주장하지 않으며 세 구간을 재사용합니다.

원본 영상·전체 추출 WAV는 공개 저장소와 사용자 ZIP에 포함하지 않습니다. 짧은 결과 WAV, 구간·처리·해시 정보는 [음원 manifest](../assets/audio/manifest.json)에 있습니다. 원본의 저작권이나 CC0 허가를 새로 주장하지 않습니다. 청취나 스피커 재생을 수행했다는 설명 없이 샘플·형식·해시 기반 검증 범위를 기록합니다.

## 2단계: 검증 범위와 현재 상태

기능별 회귀 검사는 구현과 함께 추가했습니다. 여기의 개별 검사 통과는 최종 패키지 및 Windows CI 전체 통과를 대신하지 않습니다.

| Windows Server 2022 네이티브 실행·GDI+·입력 검사 | CI 실행 결과 대기 |
| 정식 GitHub Release·latest 피드·공개 파일 재다운로드 | 검증 통과 후 진행; 아직 완료로 기록하지 않음 |

배포 도구의 권한·손상·실패 처리도 네트워크 없이 44개 검사를 통과했습니다: [배포 도구 검사](validation/v2.0.0-publisher-test.log). 음원은 [원본 대조 결과](validation/v2.0.0-reference-audio-source-check.json)를 남겼습니다.

전체 검증 진입점은 `bash tools/check.sh`입니다. 새 검사는 기존 저장 호환성과 업데이트 검사에 더해 기분·이벤트, 커서 상태 전이, 계절 옵션, 확장 외형, 표정·수면, 장난감, 실제 Box2D 공·매달리기와 두 번째 동물을 확인합니다.

공개 체크아웃의 오디오 검증은 원본 없이 결과 14개의 고정 해시·형식·수준·구간 메타데이터를 검사합니다. 원본이 없는 환경에서 원본 샘플 재구성을 했다고 표시하지 않습니다. 개인 원본이 모두 있으면 그 입력의 해시를 확인한 뒤 실제 샘플을 재구성해 추가로 대조합니다.

Windows 검사는 배포할 동일 EXE의 `--self-test`와 `--render-self-test`를 사용합니다. 저장·음원 리소스 로딩, GDI+ 실제 그리기, 확장 외형·의상·얼굴·수면, 주동물과 동반 동물의 실제 Win32 입력 처리 등을 확인하도록 구성했습니다. Windows 10/11 사용자 데스크톱에서 여러 모니터·스피커·모든 창 조합을 수동 검수했다는 의미는 아닙니다.

## 3단계: 검증된 패키지만 공개

[v2.0.0 배포 워크플로](../.github/workflows/publish-v2.0.0.yml)는 수동 실행으로 다음 순서를 강제합니다.

1. 요청한 소스 버전 확인, 전체 테스트, Windows x64 빌드, ZIP·업데이트 피드 검사.
2. 같은 패키지를 Windows Server 2022로 옮겨 패키지를 재검증하고 EXE의 네이티브 검사를 실행.
3. 앞 단계가 모두 성공한 경우에만 검사한 커밋을 가리키는 Release 초안에 파일을 올리고, 다운로드·해시 대조 후 정식 공개.
4. 공개된 파일들과 공식 `latest.txt`를 다시 내려받아 고정 버전 피드·체크섬·EXE·ZIP 내용과 대조.

공식 업데이트 주소는 `https://github.com/cho-woo/yeopjari-cat/releases/latest/download/latest.txt`로 유지합니다. 자동 알림만으로 실행 파일을 교체하지 않으며 사용자가 앱 안에서 업데이트를 선택해야 다운로드·저장·교체·재시작을 수행합니다. 구버전에서 수동 업데이트할 때에도 같은 사용자 기록 폴더를 사용합니다.

배포가 끝난 뒤에는 이 문서에 실제 검사 로그, 검사한 커밋, 워크플로 실행, 공개 파일의 크기·SHA-256 및 공식 최신 피드 검증 결과를 연결해야 합니다. 그 전에는 최종 공개 및 실제 Windows 검증 완료를 주장하지 않습니다.
