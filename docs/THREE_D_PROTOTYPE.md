# Blender 직접 제작 시제품

2026-11-05에 이 개발 환경의 Blender 4.3.2에서 고양이 메시, 골격, 관절 가중치, 두 개의 애니메이션과 렌더링을 직접 생성했다. 외부 생성 서비스나 구입 자산은 사용하지 않았다. 현재 배포 프로그램의 그림이나 동작을 교체한 결과는 아니다.

## 확인한 내용

- 하나로 연결한 몸 표면에 24개 뼈로 구성된 사족보행 골격을 연결했다. 루트 외 23개는 변형용 뼈다. 척추·목·머리, 네 다리, 귀, 꼬리의 계층을 포함한다.
- `EarFlick`은 양쪽 귀만 움직인다. `PawTap`은 왼쪽 앞다리와 발의 관절을 움직인다. 두 동작 모두 머리 변환과 뼈 크기가 고정되는 것을 각 프레임에서 검사했다.
- 몸의 가중치는 정규화되어 있고 정점당 최대 네 개 관절을 사용한다. 초기 가중치는 코드에서 계산한 것으로, 아직 모든 자세의 자연스러움을 검수한 가중치는 아니다.
- `.blend`와 `.glb`를 생성했다. GLB에는 스킨 1개, 애니메이션 2개, 분리된 재질 경계 등을 포함한 정점 28,749개와 삼각형 54,740개가 들어 있다. 크기는 1,702,544바이트다.
- 내보낸 GLB의 헤더·버퍼, 유한 좌표, 관절 인덱스 범위, 가중치 합, 시간 순서, 애니메이션의 크기 고정과 실제 움직이는 관절을 별도로 검사했다.
- GLB를 빈 Blender 장면에 다시 불러와 골격 1개·뼈 24개·두 동작을 확인하고, 앞발 동작을 재생하여 관절 위치가 실제로 바뀌는지 검사했다.
- 실제 3D 장면을 Blender에서 렌더링해 기본 자세·귀 움직임·앞발 자세를 확인했다.

## 재생성

저장소 루트에서 실행한다. Blender 4.3.2에서 검증했다.

```bash
blender --background --factory-startup -t 4 --python-exit-code 1 \
  --python tools/create_3d_cat_prototype.py -- --render
```

기본 출력은 Git에서 제외하는 `build/3d-prototype/`이다. `--output 경로`로 바꿀 수 있다. `--animate`를 더하면 각 동작을 두 프레임 간격의 PNG 시퀀스로 렌더링한다. 기본 렌더러는 CPU Cycles이며, OpenImageDenoise가 없는 Blender 빌드에서도 동작하도록 디노이징을 사용하지 않는다.

- `cream-kitten-prototype.blend`: 편집 가능한 원본. `KittenRig`를 선택하고 Action Editor에서 `EarFlick` 또는 `PawTap`을 선택해 재생한다. 두 동작은 각각 33·49프레임이며 24fps다.
- `cream-kitten-prototype.glb`: 모델·재질·골격·가중치·애니메이션을 포함한 내보내기 파일. 촬영용 바닥·카메라·조명은 포함하지 않는다.
- `preview-rest.png`, `preview-ear.png`, `preview-paw.png`: 생성된 장면의 자세별 렌더링.
- `preview-eevee.png`: 같은 원본 장면을 EEVEE로 별도 렌더링한 미리보기. 기본 생성 명령에는 포함하지 않는다.
- `rig-check.json`: 원본 골격과 몸 가중치 검사 결과. `glb-check.json`은 이번 세션의 별도 내보내기 검사 기록이며 생성 스크립트가 자동으로 다시 만들지는 않는다.
- `import-check.json`: 이번 세션의 GLB 재가져오기·애니메이션 재생 검사 기록.

## 남은 작업

외형은 단순한 조형 시제품이며 기존 그림의 털·줄무늬·표정을 재현한 완성 모델이 아니다. 얼굴 리그, 접지 IK, 체중 이동, 보행, 배 까기, 점프와 착지, 다른 행동으로의 전환, 성장·체형 대응을 추가하고 검수해야 한다. 현재 앞발 클립은 관절 조작 확인용으로, 목표 접촉과 균형이 완성된 동작이 아니다.

Windows 앱의 3D 렌더러·Box2D 연동·저장 호환성·성능 검증과 배포는 이후 단계다. 이 시제품에 Windows 출시 검증을 통과했다고 표시하지 않는다.

드롭샷은 이번 세션의 호출 가능한 도구 목록에서 확인되지 않았다. 따라서 드롭샷의 3D 모델 생성·GLB/FBX 내보내기 지원 여부는 확인하지 못했다. 서비스가 3D 메시를 생성하더라도 관절·가중치·동작이 포함되는지는 따로 확인해야 한다. Blender 직접 제작에는 드롭샷 연결이나 사용자의 추가 API 키가 필요하지 않다.
