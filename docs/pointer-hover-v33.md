# 고정 포인터와 앞발 회복 v2.0.33

고양이 위에 포인터를 가만히 두었을 때 앞발을 든 자세에서 멈추고 동작이 끊기는 문제를 수정했다. v32의 마지막 측면 참조 자체가 앞발을 약간 든 보행 자세였고, 이를 펀치·착지 뒤에도 계속 유지했다. 회복 중 Watch/Rest로 바뀌면 업데이트 간격도40ms로 늘어 원본24fps의 일부 그림이80ms 동안 보일 수 있었다.

## 영상과 등록

드롭샷 MiniMax H3에서 크림·턱시도 후보를 생성하고 검사했다. 첫 후보 두 개는 끝에 발을 다시 들어 적용하지 않았다. 해당 원본48번 프레임의 네 발이 바닥에 닿은 자세를 동일 배율로 그대로 추출해 새 첫·마지막 참조로 삼았다. 참조 업로드가 완료되기 전 요청한 두 작업은 실패·환불됐고, 업로드200 응답을 확인한 뒤 최종 두 영상을 생성했다. 실제 사용한 영상은 다음과 같다.

| 외형 | 작업 ID | 선택 |
|---|---|---|
| 크림냥 | mcp_4076561e3019469b88ea8d6f41e96247 | 원본0–106,24fps,4.458초 전체 |
| 턱시도냥 | mcp_02e1eadc0740433f83680ed436d3eed6 | 원본0–106,24fps,4.458초 전체 |

원본은 `assets/video-actions/sources/hover-v33/`, 작업·프롬프트·요금은 `generation.json`, 참조·발 좌표·회복 시작점은 `identity-v29.json`, 실제 그림 등록은 `registration.json`에 보관한다. 이번 순사용640credits, 누적94개 작업·11280credits다. 실패한 두 작업은 비용0으로 기록했다. v32 identity·manifest·registration도 history에 보존했다.

새 Reach 영상은 원본24fps의 연속107장을 모두 쓴다. 크림54번·턱시도84번부터 발을 내려놓는 후반 구간을 펀치·착지 후 회복에도 사용한다. 앞발 좌표는 원본에서 표시한 뒤 보이는 불투명 발 픽셀로 제한한다. 원본 타격 구간과 실제 화면 발 접촉이 동시에 성립할 때만 놀이 접촉으로 인정한다.

불변 마스터 두 파일과367px 공통 배율은 유지했다. 행동별 높이 정규화·얼굴 변형은 하지 않는다. 눈꽃냥은 크림 원본의 같은 등록에 기존 흰 털·오드아이 재질을 적용한다.

## 행동과 갱신

포인터의 화면상 위치·속도를 관찰한다. 고양이 몸 위에450ms 이상 가만히 있으면 제자리 앞발 놀이를 끝까지 재생한다. 정지 포인터 때문에 뒤로 정렬하거나 낮은 반복 점프를 시작하지 않는다. 실제 높은 포인터·도망가는 포인터의 달리기와 도약은 유지한다.

앞발을 내리고 착지 회복을 마친 뒤1.8–2.44초 더 쉰다. 쉬는 도중 포인터가 다시 움직이면 필수 회복을 끝낸 다음 추격을 재개한다. 도약 재사용 대기 중에는 회복 시계를 다시 시작하거나 가짜 공격 접촉을 허용하지 않는다. 활성 포인터 놀이와 착지 회복은16ms 업데이트를 유지한다. 메뉴·드래그의 명시적인 일시정지는 기존 경로를 따른다.

## 검증

`--cursor-host-self-test`의 새 회귀 검사는 고양이 위65px에 독립적인 포인터를22.4초 고정한다. 세 외형 각각 네 번의 제자리 놀이, 완성된 세 번의 발 내림·쉬기, 원본107장 전체 표시, 회복·쉬기 갱신, 이동·점프 없음, 포인터 이동 후 빠른 추격 복귀를 검사한다. 기존 실제 이동 도약·턴·공중 접촉·저장 불변·OFF·메뉴·드래그·돌봄 소유권 검사도 유지한다.

`--render-cursor-play-video`는 같은60초 실제 앱 경로의 마지막5초를 고양이 위 고정 포인터로 바꿨다. 세 외형의 실제 Windows GDI+ 렌더러와 Box2D 출력으로 원본과 발 내림·캐릭터 배율을 비교한다. 메모리 안의 결정적 입력을 쓰며 데스크톱 녹화나 OS 포인터 조작은 아니다.
