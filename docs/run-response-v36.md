# v2.0.36 달리기 반응 점검

v2.0.35의 실제 키보드·Box2D·표시 포즈 진단에서 걷기→달리기는 약1초 동안 별도 전환 영상을 재생했다. 여기에 물리 모터의130ms 응답이 다시 적용되어 가속이 두 번 완만해졌다. 달리기→걷기도 동일한 문제가 있었다. 자동 달리기의 속도 계수는0.62까지 주기적으로 내려갔다. 원본 반복 영상의 앞·끝에는 거의 정지한 그림도 포함돼 있었다.

불변 원화에서 유래한 같은 옆모습을 첫·끝 조건으로 사용해 Dropshot Seedance2.5 영상 두 개를 생성했다. 총920credits다. 얼굴·눈·귀·털 무늬와 공통367px 기준을 확인하고 각 영상의 완전한12프레임 가속·감속 구간을 선택했다. 각 구간은 원본24fps의500ms다. 원본960px 영상과, 전체 캔버스에 동일한0.8배 축소만 적용한768px 무손실 FFV1 파생본을 보관한다. 인코딩 전후의 모든 BGR 픽셀 해시를 확인한다. 자세별 높이 조절은 하지 않는다.

기존 달리기 반복의106장과523px 실측 보폭은 그대로 유지한다. 반복 시작·끝8장 안에서 시각 변화가 매우 작은 프레임만 실제 이동 거리에 차지하는 비중을 줄였다. 모든 그림은 양의 구간을 가지며 순서를 유지한다. 중앙90장의 거리 비중은 동일하다. 원본24fps 재생 정보는 바꾸지 않는다. 고양이가 이동 중인데 영상의 정지한 끝 자세를 같은 시간 동안 유지하는 현상을 줄이기 위한 표시 거리 시계다.

가속·감속과 턴 후 출발에는 물리 응답에 맞는 미분 선행 보상을 사용한다. 모터 목표가 순간적으로 계획 속도보다 높을 수 있지만, 실제 속도는 Box2D의 가속도 제한과 지면 접촉을 따른다. 같은 방향의 입력 변화가 동작 소유권·걷기 진입을 다시 시작하지 않는다. 턴의 제동·피벗·출발 프레임과 완전한 회복 구간은 자르지 않는다. 영양·종별 속도 계수는 한 번만 적용되도록 시작 속도의 단위를 맞춘다.

일반 자동 달리기는0.90~1.10 사이의 작은 속도 변화만 사용한다. 키보드에서는 입력 속도를 우선하고 자동 리듬을 적용하지 않는다. 두 번째 고양이에도 같은 시계와 가속·감속·일반 달리기 정책을 적용한다. 저장 형식, 돌봄 기록, 실제 사용자 입력은 변경하지 않는다.

원본·생성 요청·선택·등록은 `assets/video-actions/sources/run-v36/`, `selected/run-v36/`에 보관한다. 변경 전 등록은 `history/v36-before-run/`에 남긴다. 검사는 실제 물리 모터의500ms 가속·감속과 턴 후 출발, 세 외형과 동반 고양이의 정상 키보드 호스트, 느린 반복 경계의 화면 고정 시간을 포함한다. 최종 Windows CI와 정확한 패키지 검증 후 배포한다.

세 외형을 같은 배율로 검토하며 눈꽃냥의 달리기에서 따뜻한 털 색이 분홍 피부로 남는 기존 재질 오인을 확인했다. 달리기 재질만 실제 분홍색의 청색/녹색 성분으로 구분한다. 크림·턱시도106장 원화와 모든 알파·실루엣은 유지하며 코·귀·발바닥의 실제 분홍색을 보존한다.

최종 검토에서60Hz 원본 대조가 빠진102번 그림을 검출했다. 최소 거리 구간을 원본 평균의 절반 이상으로 제한하여110% 속도에서도 각 그림에 한60Hz 표시 간격 이상의 여유를 둔다. 기존의 전체106장 실제 표시 검사는 그대로 유지한다.
