# 포인터 추격·공중 잡기 v2.0.32

기존 반복 놀이 경로는 포인터가225px 밖으로 나가면 취소했고, Chase/Punch 분기를 사용하지 않았다. 새 경로는 같은 모니터에서 포인터의 속도를75ms 시정수로 관찰하고, 앞쪽 위치를 예상해 같은 지상 모터로 추격한다. 가까이에서는 실제 소스 앞발 높이에 맞는 간격까지 접근한다. 메뉴·드래그·숨김·OFF·키보드 조작·식사·수면·다른 행동의 소유권은 기존과 같이 우선한다.

달리던 고양이는 모터의 실제 수평 속도를 유지하고 Box2D의 `JumpWithMomentum`으로 뛰어오른다. 발사 후에는 포인터를 따라 물리 궤적을 조작하지 않는다. 화면 끝에서는 착지·제동 공간을 먼저 검사한다. 정지 상태와 ‘이 자리에서 쉬기’는 기존의 수직/같은 지지면 도약을 쓴다. 실제 상승·하강 진행률과 지면 접촉이 도약 아트의 비행·착지 구간을 고른다.

도약 판단은 현재 거리만으로 하지 않는다. 고양이와 포인터의 상대 수평 속도로625ms 준비와 실제 예상 상승 시간을 지난 뒤의 간격을 계산한다. 다가오는 포인터에는 일찍 뛰어들고, 같은 속도로 달아나는 포인터에는 접근을 더 이어간다. 발을 떼기 전까지 높이와 목표를 갱신하며 포인터가 뒤로 지나가면 지상 추격으로 전환한다. 발을 뗀 뒤에는 목표와 실제 물리 궤적을 고정한다.

공중에서 겨냥하는 앞발 길이·높이도 각 캐릭터의 실제 소스 중간 비행 프레임과 현재 체형에서 계산한다. 점프 능력은 최대 도달 높이를 제한하며, 도달 가능한 포인터에 필요한 높이를 일부러 낮추지 않는다. 접촉은 현재 물리 스텝보다 앞서거나 뒤처진 가상 좌표가 아니라 화면에 그리는 보간 위치와 발 좌표로 검사한다.

착지와 펀치 뒤에는 영상의 네 발 자세를 유지한다. 착지 회복을 끝내고180ms, 연속 펀치 회복을 끝내고280ms 뒤 다시 목표를 선택한다. 도망가는 포인터에는 추격을 재개한다. 추격 중 반대 방향으로 바뀌면 기존 드롭샷 달리기 턴을 끝까지 보이며, 턴 도중 다른 공격으로 덮어쓰지 않는다.

## 생성 원본과 적용

사용자가 요청한 드롭샷 연결로 MiniMax H3 영상4개를 생성했다. 각160credits, 합계640credits다. `assets/video-actions/generation.json`에 프롬프트·작업ID·참조·결과 URL을, `sources/cursor-v32/`에 MP4 원본을 보관한다. 전체 기록은88개 작업 /10640credits다.

| 캐릭터·행동 | 드롭샷 작업 ID | 선택한 원본 프레임(24fps) |
|---|---|---|
| 크림냥 연속 펀치 | mcp_733274107da342df8b16accfb6851506 | 14–82, 연속69장 |
| 턱시도냥 연속 펀치 | mcp_1141f4d924404e98aeb8f1216fb06c87 | 18–86, 연속69장 |
| 크림냥 전방 도약 | mcp_fa51bb8631a246c69ba2096daca25c60 | 34–99, 연속66장 |
| 턱시도냥 전방 도약 | mcp_a7ab03b3539e417c99e85c2b4fb80127 | 17–82, 연속66장 |

펀치는 원본24fps의2.875초 연속 동작이다. 도약은15장 준비(625ms),25장 비행,26장 착지·회복(1083ms)으로 나누며 비행만 실제 물리 진행에 맞춘다. 기존 일반 점프와 분리한 `CursorPounce` 등록을 사용한다. 기존 펀치 atlas를 교체해 추가 아트가 실행 파일128MiB·두 재질256MiB 상주 제한에 들어가도록 한다.

모든 생성의 첫·마지막 프레임은 기존 오른쪽 측면 원화로 고정했다. `identity-v29.json`의367px 공통 배율을 사용한다. 포즈별 높이 정규화나 얼굴 변형을 하지 않는다. 눈꽃냥은 기존 재질·홍채 마스크 경로로 같은 alpha와 등록을 공유한다. 마스터 `assets/cat.png`, `assets/styled-sprites/c8-r101.png`는 변경하지 않았다. v31 manifest·identity·registration은 `history/v31/`에 보존했다.

발 좌표는 원본에서 주석을 달고 보이는 불투명 픽셀 안으로 제한한다. 펀치의 실제 내리치는 구간과 도약의 앞발 뻗기 구간만 접촉을 허용한다. 실제 앞발과 현재 포인터 간 거리 검사에 통과해야 하며, 같은 타격의 중복 콜백은 기억/보상을 다시 만들지 않는다. OS 포인터 이동·클릭은 주입하지 않는다.

## 검증 경로

`--cursor-host-self-test`는 앱의 실제 샘플·행동 소유권·모터·물리·표시 포즈·접촉 함수를 사용한다. 기존 OFF/일시정지/돌봄/직렬 소유권 검사에 세 캐릭터 ×8/16/33ms의 움직이는 포인터·수평 속도 보존·달리기 턴·좌표 연속성·저장 불변 검사를 추가했다.

별도로 높이120px에서 초당72px로 일정하게 이동하는 독립적인 포인터 경로를 실행한다. 세 캐릭터와 보통/무거운 두 체형의6개 경우 모두 실제 공중 앞발 접촉이 한 번 이상 있어야 통과한다. 테스트 포인터를 고양이 발 위치에 맞춰 옮겨서 성공시키지 않는다.

`--render-cursor-play-video`는 같은 실제 앱 경로와 GDI+ 렌더러로 세 캐릭터의60초·60fps 비교 프레임과 JSON 추적을 만든다. 정지 포인터 펀치 → 도망가는 높은 포인터 추격/도약 → 양 끝으로 바뀌는 포인터/턴 → 이동 정지 상태의 수직 도약 → 포인터 소실/복귀 → 실제 Eat 행동의 우선권 → 놀이 재개를 다룬다. 메뉴·드래그의 실제 FreezePrimaryMotion 경로도 검사한다. 입력은 메모리 안의 결정적 샘플이며 데스크톱 녹화나 OS 입력 주입은 아니다.

세 재질을 동시에 상주시키지 않는다. 각 캐릭터를 실제 렌더러로 그린 불투명 영역의 premultiplied 픽셀을 임시 저장한 뒤, 합성할 때 원본 해시와 일치하는지 확인한다. 이 진단용 임시 픽셀은 합성 후 제거한다.

공개 릴리스에는 검증한 실제 앱 비교 영상과 드롭샷 원본을 첨부한다.
