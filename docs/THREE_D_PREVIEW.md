# 옆자리 고양이 — 앱에 연결한 3D 시험판

이 작업은 기존 2D 정식판과 별도로 실행하는 Windows 10/11 x64 시험판이다. 정식판의 그림·저장 기록·업데이트 피드를 교체하지 않는다. 소스 브랜치는 `codex/3d-preview`다.

## 구현

- Blender에서 둥근 볼, 짧은 목, 크림·치즈색 털 무늬, 작은 털 가닥, 눈·귀·꼬리를 갖춘 모델을 직접 제작했다. 머리의 뒤통수와 턱은 머리 관절을 따르며, 꼬리 끝이 귀에 연결되지 않도록 제작 시 검사한다.
- 26개 뼈를 사용한다. 걷기·달리기·살금살금은 네 발의 접촉 구간과 들리는 구간을 나누고, 두 관절 역기구학으로 발 위치를 맞춰 제작한다. 배 까기는 몸의 긴 축으로 옆으로 눕고 구르며, 머리와 꼬리를 따로 조정한다.
- 기존 앱에 Direct3D 11 렌더러를 연결했다. 실제 골격을 보간하고 표면을 변형한 뒤 조명·재질·깊이·안티앨리어싱을 적용해 투명 창에 합성한다. 기본적으로 하드웨어를 사용하며 초기화가 실패하면 WARP를 시도한다.
- Box2D가 위치·이동·점프·창 지지면과 낙하를 계속 계산한다. 애니메이션은 물리 이동 거리를 따르고, 카메라 각도에 따른 보폭 투영도 반영한다. 공중 동작에 별도 점프 궤적을 중복 적용하지 않는다.
- 첫 번째 크림 치즈냥의 기본 자세·보행·살금살금·달리기·배 까기·공중 자세·착지·귀·앞발에 3D를 적용한다. 다른 캐릭터와 아직 대응하지 않은 동작은 기존 2D 경로를 사용한다.

## 실행

검증된 `YeopjariCat-3D-Preview.zip`을 별도 폴더에 풀고 `3D-preview.cmd`를 실행한다. 실행 파일과 `cat3d.bin`은 같은 폴더에 둔다.

시험 기록은 `%LOCALAPPDATA%\YeopjariCat-3D-Preview`에 저장한다. 정식 기록 폴더 `%LOCALAPPDATA%\YeopjariCat`와 별개다. 시험판은 정식 업데이트를 확인하거나 설치하지 않고 전역 단축키도 등록하지 않는다. 밥·츄르와 기존 메뉴는 사용할 수 있으며 동작은 자동으로 발생한다.

## 빌드와 검사

```bash
bash tools/test.sh
python3 tools/audit_3d_model.py --model-dir assets/3d/cream-kitten \
  --output build/3d-preview-runtime-audit.json
bash tools/build_3d_preview.sh
```

`tools/test.sh`는 기존 회귀 검사와 새 골격 로더·보간 검사를 실행한다. 모델 감사는 실제 C++ 런타임으로 각 클립의 프레임과 중간 시점, 동작 간 전환을 계산하여 유한 좌표·법선·머리 크기·접지·발 미끄러짐을 검사한다. 큰 수직 오차가 생기는 임의의 중간 자세 전환도 보고서에 남긴다.

[Windows 검사 워크플로](../.github/workflows/verify-3d-preview.yml)는 ZIP 크기·해시·CRC·무음, 기존 네이티브 테스트, Direct3D WARP의 깊이·투명도, 45개 자세와 177개 연속 모션 프레임, 실제 투명 앱과 Box2D 이동, 정식 저장 폴더의 미변경을 확인한다. 통과한 경우에만 검증된 시험 ZIP을 Actions 산출물로 제공한다. GitHub Release나 공식 업데이트 피드를 게시하는 작업은 없다.

Blender 미리보기와 Linux CPU 검토 그림은 보조 자료다. 실제 Windows Direct3D 출력과 구분한다. 모델 원본의 재생성은 [자산 설명](../assets/3d/cream-kitten/README.md)을 따른다.

## 남은 범위

외형은 사용자 검토가 필요한 후보이며 기존 그림의 모든 털과 표정을 재현한 완성 모델이 아니다. 다른 캐릭터, 모든 생활 행동, 성장·체형의 3D 표현을 완성해야 전체 전환이 가능하다. 대응하지 않은 행동에서 2D로 바뀌는 것은 이 시험판의 한계다.

배 까기를 끝까지 재생한 뒤 다음 행동으로 넘어가는 경우와 달리, 도중에 강제로 다른 행동으로 바뀌면 짧은 보간 중 수직 흔들림이 남을 수 있다. 바닥 접지를 다시 맞추지만 이것이 자연스러운 일어나기 동작을 완성했다는 뜻은 아니다. 행동별 중단·회복 동작과 실제 사용자 GPU에서의 장시간 성능 검증도 필요하다. 이러한 한계를 해결하기 전 정식판의 기본 표시로 전환하지 않는다.
