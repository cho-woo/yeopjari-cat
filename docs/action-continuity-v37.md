# v2.0.37 행동 연결 점검

전체 행동을 단순한 미리보기 대신 실제 `PrimaryDisplayedPose` → GDI+ 표시 경로로 검사한다. 32개 행동 × 크림·턱시도·눈꽃 3종의 시작, 진행, 복귀를 60Hz로 추적하고, 세 외형의 제동·미끄러짐·넘어짐 9개 경로를 추가로 검사한다. 화면상 그림 중심과 Box2D 물리 좌표를 따로 기록하므로 그림 보정으로 순간이동을 숨길 수 없다. 사용자 저장 파일과 OS 입력은 바꾸지 않는 독립 실행 검사다.

## 확인한 원인과 수정

- 깃털·그릇의 가장 낮은 픽셀을 고양이 발바닥으로 잘못 사용했다. 깃털 놀이의 원본 바닥 좌표가 544→582로 변하면서 고양이가 약 11픽셀 위로 튀었다. 장난감·식사·생선은 소품과 무관한 기록된 고양이 접촉 바닥에 고정했다.
- 기존 그림 기반 행동에서 서로 다른 자세를 바로 교체했다. 고정 관측 기준 구르기·스트레칭·매달리기 경계의 그림 중심이 한 프레임에 약 18~26픽셀 변했다. 행동 소유권 식별자와 표시 상태를 함께 추적하고, 몸 중심을 등록한 짧은 경계 연결을 적용했다. 큰 자세 차이는 한 몸으로 연결해 머리가 겹치는 전환을 피한다. 이동 중 발 접촉, 공중 동작과 영상 내부 프레임은 직접 표시한다.
- 일반 앞발 놀이가 기존 12장 번호를 107장 펀치 영상에 전달해 준비 동작만 반복했다. 실제 시간으로 전체 영상과 회복을 선택하도록 수정했다. 포인터·공·낚싯대는 각자의 접촉 소유권과 시간을 유지한다.
- 기존 제동 영상은 정면에서 시작해 달리는 옆모습과 충돌했다. 새로운 옆모습 시작 영상을 적용하고, 완료 후 걷기 복귀 영상이 다시 끼어들던 처리를 제거했다. 실제 감속과 영상 회복이 모두 끝난 다음 45~100초 휴식 시간을 시작한다.
- 동반 고양이의 명시적인 ‘놀아주기’가 3초에 끝나 펀치 영상의 회복을 잘랐다. 등록된 전체 영상 길이를 사용하고 세 외형에서 마지막 회복 그림을 본 뒤 휴식에 들어가는지 검사한다.
- 화면 횡단 이벤트가 투명해진 뒤 반대편에 좌표를 재설정했다. 화면 안에서 실제로 걸어서 이동하도록 바꿨다.
- 눈꽃 외형은 주황색 털이 회색 줄무늬로 남거나, 머리가 회전할 때 눈 색이 바뀌었다. 피부·소품·알파를 보존하는 털 재질과 회전 중 해부학적 눈 식별 추적을 적용했다. 동일 크기의 세 외형을 함께 확인한다.

[세 외형의 실제 앱 구르기 출력](previews/v2.0.37/roll-native-board.png). 60Hz 표본에서 고른 연속 동작이며 바탕화면 녹화가 아니다.

## 새 드롭샷 원본

`selected/continuity-v37/`에 생성 요청·작업 ID·모델·비용·SHA-256·선택 범위를 보관한다. 12개 Seedance 2.5 작업, 총 5,520크레딧이다. 기존 크림·턱시도 원화와 정확한 시작·끝 이미지로 생성했으며 원본 MP4는 `sources/continuity-v37/`에 남긴다.

- 자세 정리 2개: 원본 97프레임 중 완전한 웅크림·복귀가 포함된 0~72를 원래 24fps로 사용한다. 뒤의 반복된 정지 구간도 원본에 보관한다. 수면 기상은 기존 전용 영상을 유지한다.
- 구르기·꼬리 쫓기 4개: 시작부터 지지·회전·앞발 놀이·앉기 복귀까지 0~96 전체를 사용한다.
- 제동·미끄러짐·넘어짐 6개: 옆모습 발 짚기에서 시작해 정면의 지지 자세로 돌아오는 0~96 전체를 사용한다. 입력 이미지 캔버스 차이에서 오는 바닥 오차는 양 끝의 기록된 바닥만 선형 보정한다.

공통 원화 높이 367, 앱용 기준 높이 96을 유지한다. 프레임별 자세 높이로 크기를 다시 맞추지 않는다. 원본 얼굴·귀·무늬·비율을 바꾸지 않고 크림과 턱시도 원화 파일은 그대로 보존한다. 눈꽃은 동일한 기하·알파에서 재질만 바꾼다.

## 재현과 검증

`tools/prepare_continuity_v37.py`가 검토된 새 제동 원본과 선택 정보를 등록한다. `tools/pack_video_actions.py`가 영상 프레임·접촉·재질을 추출하고 기존 import 도구가 리소스를 만든다. 선택 기록과 `provenance.json`으로 모든 원본을 추적한다. `lossless-encoding.json`은 자산 교체 전 무손실 최적화 기록이며, 최종 자산 해시는 manifest와 provenance를 기준으로 한다.

`--render-action-continuity`는 105개 전체 경로의 `report.json`, `trace.csv`, 최악 경계의 전후 이미지를 출력한다. 물리 속도에 맞지 않는 위치 단절이나 110픽셀 표시 기준 한 프레임 16픽셀 초과 중심 변화는 실패한다. `--render-source-audit`와 배포 CI에도 포함한다. 이 기준은 회귀 검출을 위한 것으로 가능한 모든 상호작용을 수학적으로 보장하지는 않는다.

기존 자동 검사로 포인터 급반전·근거리 펀치·키보드 걷기/달리기/턴·이동 점프·공놀이·파리 사냥·식사·그루밍·동반 고양이·캐시 한도·업데이트 알림도 유지한다. 완전한 원본 걷기/달리기 루프 및 106개 달리기 프레임 커버리지는 그대로 검사한다. 배포 파일은 CI에서 검사한 정확한 파일만 사용한다.

24개 등록 클립(기존 간식·호환 자산 포함)의 타이트 프레임은 외형 하나당 139,922,528바이트다. 두 활성 외형의 완전한 동작·회복을 메모리에 유지하기 위해 합산 캐시 상한을 256MiB에서 320MiB로 조정했다. 활성 외형 두 개만 남기는 정책, 개별 이미지 크기 제한과 상한 초과 거부 검사는 유지한다. 각 프레임을 축소하거나 일부 회복 장면을 빼서 한도에 맞추지 않는다.

제동 진입은 단순한 중심 이동 상한 외에, 실제 직전 달리기 그림에서 시작하는지 별도로 검사한다. 회귀를 재현한 9개 진입에서 첫 제동 프레임의 화면 중심 변화는 1픽셀 이하여야 한다. 이동 중 달리기 프레임은 직접 표시하며 제동으로 연결할 마지막 그림만 보관한다.
