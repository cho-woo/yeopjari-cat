# v1.10.0 친밀도·기억·생활 패턴

v1.9.0의 복원 소스와 v1.9.1 동작 수정 위에 첫 번째 로드맵을 구현했습니다. 기존 행동·이미지·소리·Box2D와 업데이트 프로토콜을 유지합니다. 커서 사냥, 새로운 창 사이 점프, 의상·계절·품종과 두 마리 기능은 이후 버전의 작업입니다.

## 사용자에게 보이는 변화

- 실제로 받아먹은 밥·츄르, 깨어 있을 때의 쓰다듬기, 사용자가 꺼내 준 장난감이 기억에 반영됩니다. 거절한 먹이와 자동 놀이는 돌봄 실적으로 만들지 않습니다.
- 처음에는 낯을 가리며, 친밀도가 35 이상이면 가끔 같은 발판의 가까운 커서 쪽으로 천천히 다가와 조금 떨어져 멈춥니다. 커서가 멀어지거나 이동을 일시정지하면 그만둡니다. 이미 가까이 있는 커서의 반대 방향으로 움직이지 않습니다.
- 쓰다듬는 습관은 배 까기·꾹꾹이 빈도에, 츄르 습관은 조용한 츄르 요청에 반영됩니다. 배고플 때는 밥 요청을 우선하며 배부르면 츄르도 조르지 않습니다.
- 현지 시각 7~10시 기지개, 11~14시 배고플 때 점심 요청, 14~18시 우다다 빈도 증가, 22~5시 수면 빈도 증가, 2~5시 일부 날에 짧은 우다다가 가능합니다. 자거나 먹거나 메뉴가 열렸거나 숨긴 동안 새 행동으로 끊지 않습니다.
- 90일/친밀도 25부터 `꾹꾹이 → 식빵`, 1주년/45부터 `꼬리 세우기 → 배 까기 → 바라보기`, 5주년/65부터 `기지개 → 꾹꾹이 → 식빵 → 잠`의 특별한 말풍선 시퀀스가 해금됩니다. 기존의 일반 꾹꾹이·배 까기는 계속 가능합니다. 특별 시퀀스는 12시간 공통 간격으로 제한됩니다.
- 성장 기록 창에서 친밀도와 기억한 돌봄 성향을 확인합니다. 생일에서 파생한 기본 성격은 보존하고, 돌봄 경험이 행동 성향을 아주 천천히 보정합니다.

## 저장과 자동 초기화

기존 `pet.ini`, `nutrition.ini`, `preferences.ini`, 소리·업데이트 설정의 형식과 위치를 유지합니다. 새 `memory.ini`와 `memory.bak`만 `%LOCALAPPDATA%\YeopjariCat`에 추가합니다. 두 파일이 모두 없을 때만 기존 생일·식사·츄르 횟수에서 초기화합니다. 초기 친밀도는 관측된 돌봄과 함께한 기간에 따라 최대 35이며, 돌봄 기록이 없으면 0입니다. 과거 쓰다듬기·놀이 횟수와 과거 학습 결과는 만들어 내지 않습니다.

기억 파일에는 생일, UTC 시각, 친밀도, 돌봄 횟수·습관, 성격 보정, 최근 돌봄·생활 행동 시각과 체크섬을 저장합니다. 다른 생일·알 수 없는 스키마·중복 필드·잘린 내용·범위 초과·NaN 등은 읽기를 거부합니다. 정상 백업이 있으면 복구합니다. 둘 다 읽을 수 없으면 원본을 보존하고 기억 학습을 중단하며 안내합니다. 기존 성장·캐릭터·체형은 계속 사용합니다.

저장은 임시 파일 생성 → flush → 재읽기 일치 검사 → 정상 이전 파일 백업 → 원자적 교체 순서입니다. 손상된 파일은 덮어쓰기 전에 별도 보존합니다. 저장 시작 시와 교체 직전에 파일의 존재·읽기 성공 여부·내용을 확인하여 오래된 세션이 최신 기억을 덮어쓰지 않게 합니다. Windows에서는 저장 폴더별 전역 mutex도 사용합니다. 실패 시 이전 파일을 유지하며 반복 알림·매 프레임 재시도를 제한합니다.

메뉴의 성장 기록 내보내기는 예전과 같은 생일·성장 파일입니다. 모든 기억·설정을 백업하거나 PC를 옮기려면 앱을 종료하고 저장 폴더 전체를 복사합니다. 다른 생일의 성장 파일만 복원하면 기존 기억과 섞지 않고 기억 학습을 중단합니다.

## 속도와 시간 경계

친밀도 상승은 한 번에 0.05~0.07, 공통 5분 간격, 최근 24시간 내 최대 24회로 제한합니다. 연속 클릭이나 재시작으로 몇 년의 관계를 즉시 만들 수 없습니다. 장기 부재는 친밀도를 지우거나 가상의 돌봄을 추가하지 않습니다.

습관은 최근 인정된 돌봄의 완만한 이동 평균입니다. 성격은 이전까지의 습관에서 하루에 한 번만 학습하며 각 항목의 변화는 최대 0.0015, 총 보정은 ±0.15입니다. 부재 기간을 한꺼번에 학습하지 않습니다. 성격 이름은 새 후보가 기존 성격보다 충분히 강할 때만 바뀌므로 사소한 변동으로 계속 오가지 않습니다.

친밀도 접근은 최소 30분, 츄르 요청은 6시간 간격에 기존 식사·요청의 2시간 간격도 함께 적용합니다. 하루 행동은 현지 날짜와 UTC 최소 20시간 간격을 함께 확인합니다. 희귀 행동 기회는 생일과 5분 단위 시각에서 결정하여 프레임 수나 재시작 횟수에 따라 확률이 부풀지 않습니다. 시계 역행 중에는 새 기억·생활 기회를 적립하지 않습니다. 윤년 생일의 1주년·5주년은 기존 기념일 계산을 사용합니다.

## 검증 범위

`bash tools/check.sh`가 기존 회귀 검사와 다음 새 검사를 실행한 뒤 Windows x64 크로스 빌드·한글 리소스·ZIP·업데이트 피드를 검증합니다.

- 기억 초기화, 직렬화, 잘못된 필드·체크섬·시계·연속 입력·하루 제한과 점진적 학습.
- 저장 실패·부분 쓰기·재읽기 불일치·백업 복구·다른 생일·동시 세션·저장 중 파일 변경 주입.
- 점심·츄르 요청과 영양 모델의 유효성, 모든 바쁜 상태·이동 정지·시간대·쿨다운·희귀 해금 경계.
- 2020년 윤년 생일부터 10년간의 돌봄과 100회 이상 저장/재시작: 연속 실행과 복원한 상태 일치, 부재 처리, 다른 돌봄 성향, 기본 성격 유지.
- 가까운 커서·화면 끝·발판 밖·부호·거리·NaN에서 안전한 접근 목표 계산.

Linux 모델 검사와 크로스 빌드는 실제 Windows 10/11의 화면·소리·업데이트 중 실행 파일 교체를 실행한 검사가 아닙니다.
