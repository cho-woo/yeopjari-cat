# 돌봄 동작 시트 연결 — 작업 중

이 문서는 검토용 구현 상태다. 대화의 인라인 참고 이미지는 확인했지만 원본 PNG 바이트는 아직 가져오지 못했다. 첨부된 `점프.zip`도 다운로드 도구의 단일 파일 32MiB 상한에 걸려 읽지 못했다. 현재 `kCareSprites.size() == 0`이며 실제 동작 시트는 하나도 포함되지 않았다. 새 버전·릴리스는 만들지 않았고 정식 v2.0.9와 업데이트 피드를 유지한다.

## 연결 범위

| 클립 | 격자·프레임 수 | 연결한 재생 규칙 |
| --- | --- | --- |
| `groom` | 4×4 · 16 | 기존 랜덤 몸단장 이벤트에서 4–8초 재생 |
| `sleep` | 4×3 · 12 | 도입 0–1 → 수면 2–7 반복 → 기상 8–11 |
| `box` | 4×2 · 8 | 박스에 도착한 뒤 앞발·들어가기·숨기·빼꼼 순서 |
| `fish` | 4×2 · 8 | 허용된 생선 급식이 승인된 경우 재생 |
| `punch` | 4×3 · 12 | 준비·두 번의 타격·회복; 기존 300/600ms 효과 시점 유지 |
| `eat` | 3×4 · 12 | 도입 0–1 → 씹기 2–8 반복 → 마무리 9–11; 기본 5초 |
| `jump` | 4×4 · 16 | 실제 접지·수직 속도로 웅크림·상승·정점·하강·착지 선택 |
| `treat` | 6×4 · 24 | 도입 0–5 → 핥기 6–14 반복 → 마무리 15–23; 기본 4.2초 |

선택적으로 포함된 PNG는 `DrawCareSprite`가 그린다. 프레임별 고정 앵커와 클립 공통 `reference_height`를 사용하며, 각 자세의 알파 경계에 맞춰 따로 확대하지 않는다. 완성 시트가 선택된 경우 기존의 추가 흔들림·회전·표정 변형을 끄고 한 프레임씩 표시한다. 해당 캐릭터·클립의 원본이 없으면 기존 그림으로 재생한다.

점프 높이와 이동은 계속 Box2D가 결정한다. 비접지 상태에서 도착 예정 시각만으로 착지 그림을 내보내지 않는다. 수면 기상은 기존 기지개 상태에서 880ms 재생하며 다른 수면 자세와 창 위 졸기 경로를 유지한다. 박스 시트는 실제 박스 위치에 정렬되어 멈춘 상태에서만 사용한다. 해당 시트가 있을 때만 방문 시간을 3,350ms로 늘린다.

`생선 주기`는 첫째·둘째 고양이 메뉴와 급식 로직에 연결했다. 강아지·토끼에는 비활성화한다. 생선은 기존 식사로 기록되어 포만감·거절·먹이 간 공통 대기 시간·식사 횟수·기억 규칙을 공유한다. 생선 표시 플래그는 일시적이며 저장 형식을 추가하지 않는다.

추가로 요청된 수면 8종 콘셉트와 손흔들기 12프레임은 아직 별도 클립에 매핑하지 않았다.

## 원본 가져오기

원본은 **실제 투명 배경을 가진 비인터레이스 8비트 RGBA PNG**여야 한다. 각 프레임에도 투명 여백과 보이는 그림이 있어야 한다. 흰색·검은색·체커보드 배경을 추측해서 지우거나 누락된 그림을 생성하지 않는다.

아래 예시는 각 칸이 320×320px인 크림냥 몸단장 시트를 가정한다. `anchor`는 모든 칸에서 같은 지지점을 가리키는 칸 내부 좌표다. 실제 원본의 크기·지지점에 맞춰 값을 정한다. `source`는 매니페스트가 있는 폴더 기준 경로다.

```json
{
  "schema": 1,
  "clips": [
    {
      "clip": "groom",
      "character": 0,
      "source": "groom.png",
      "columns": 4,
      "rows": 4,
      "reference_height": 300,
      "anchor": [160, 300]
    }
  ]
}
```

```sh
python3 tools/import_care_sprites.py --manifest /path/to/manifest.json
python3 tools/import_care_sprites.py --check
```

가져오기는 PNG 바이트를 그대로 `assets/care-sprites/`에 복사하고 정규 매니페스트와 C++/리소스 목록을 생성한다. `--check`는 읽기 전용으로 원본 체크섬·프레임·생성 파일의 일치를 검증한다. 칸마다 여백이 다르거나 설명문이 포함된 시트는 `frames`에 각 `rect: [x,y,width,height]`와 `anchor: [x,y]`를 명시한다. 이때도 클립의 기준 높이는 공통으로 유지한다.

병합·배포 전에는 실제 원본을 가져와 얼굴·크기·발 지지점·배경·박스 가림을 검토하고, Windows에서 실제 PNG를 그리는 검사와 창 이동·낙하·착지를 확인해야 한다. 이어 Windows x64 빌드·회귀 검사·ZIP·업데이트 피드 검증을 통과한 경우에만 배포한다. 현재 빈 목록의 통과 결과는 원본 시트의 시각 품질 검증을 대신하지 않는다.
