# v1.9.0 소스 복원 및 재빌드 검증

검증일: 2026-11-03. 현재 정식 버전과 소스 버전은 1.9.0으로 유지합니다.

## 복원 근거

기존 저장소는 README, 과거 배포용 델타/체크섬·매니페스트, 소스 압축 파일과 배포 워크플로로 구성되어 있었습니다. 일반 개발용 소스 트리나 독립 검증 CI는 없었습니다. v1.3~v1.7 워크플로는 배포 파일 복원·검증·공개, v1.8~v1.9는 소스 복원·에셋 추출·Box2D/LLVM 다운로드·테스트·빌드·공개를 한 작업에서 처리했습니다. v1.8은 워크플로에서 소스 두 곳을 수정했지만 v1.9 빌드는 소스에 추가 패치를 하지 않습니다. 과거 파일은 삭제하지 않고 보존했습니다. 워크플로 원문만 `docs/history/workflows/`로 이동했습니다.

`build-inputs/v1.9.0/yeopjari-src-1.9.0.tar.gz`를 기존 v1.9 CI가 고정한 SHA256 `9ae05050d4cf9222cfa05832d254e76f940a2d89a7464b4343c97669a1e9d78b`로 검증한 뒤 복원했습니다. Python 캐시와 바이너리 출력은 복원 대상에서 제외했습니다. 원본 `src/` 19개, `tests/` 11개, `tools/` 4개 및 `build.sh`를 바이트 그대로 보존했습니다. 정리 이후 추가한 도구·검사 외에 런타임 코드는 변경하지 않았습니다.

이미지 6개와 음원 14개는 원래 CI와 동일하게 v1.8.0 공개 ZIP의 EXE에서 RCDATA로 추출했습니다. 기준 ZIP SHA256은 `5b8f7dfe15f015fa980494a92f682fef62534f5f002cd768bd12288e80c12e28`입니다. 공개 v1.9.0 EXE와 빌드 결과의 `.rsrc`도 일치하여 동일한 에셋임을 확인했습니다. 사용자 설명서·제3자 고지는 검증한 정식 v1.9.0 ZIP에서 복원했습니다. 다운로드나 PE 추출은 앞으로의 일반 빌드에 필요하지 않습니다.

`v1.9.0-files.json`은 복원 직후의 원본 소스·테스트·도구·에셋 해시 목록입니다. 이는 이번 구조 정리의 기준 자료이며, 앞으로 소스 수정 시 현재 파일이 이 해시와 계속 같아야 한다는 의미는 아닙니다. 제3자 고지와 원본 에셋을 함께 유지하세요.

## 실행한 검증

새 루트 소스 트리에서 `bash tools/setup.sh`, `bash tools/check.sh`를 실제 실행했습니다. 설치 재실행도 성공했습니다.

- C++ 테스트 실행 파일 9개 통과: 행동 11,621, 애니메이션 12,031, 체형/영양 1,482, 캐릭터/의상 66, 업데이트 알림 47, 소리 1,927, 저장/달력 288, 업데이트 프로토콜 684, Box2D 물리 414 검사. 합계 28,560 검사.
- Python 20개 중 19개 통과, 1개 건너뜀. 원본 배포·한글 리소스 검사에 baseline 비교 도구 검사 2개를 추가했습니다. 건너뛴 검사는 과거 v1.5 EXE의 깨진 한글 재현이며 해당 EXE가 체크아웃에 없어서 실행되지 않았습니다.
- 고정 LLVM-MinGW 및 Box2D로 Windows x64 정적 링크 빌드 통과.
- 실제 EXE의 RT_DIALOG 201에서 한국어 문자열 5개 검증 통과.
- 로컬 배포 ZIP 구성·해시·버전·업데이트 피드 검증 통과.
- 공개 v1.9.0 ZIP SHA256 `5012f225a338363f28d1f9e2f60e99dcf93b697209d487d71dc466c7b6967a5c` 확인.
- 공식 latest 피드가 stable v1.9.0을 가리키며 실제 EXE의 크기 11,623,936 bytes와 SHA256 `72c3a5177c9a17714dcf10f2c0298517f0ec0fafa9f4b86c19a1599a9848e6b2`에 일치함을 확인. 피드의 EXE URL을 실제로 다운로드해 해시도 확인했습니다.

실행 로그는 [validation/v1.9.0-check.log](validation/v1.9.0-check.log), 공개 빌드 비교 결과는 [validation/v1.9.0-baseline.json](validation/v1.9.0-baseline.json)에 보존했습니다. 로그의 절대 경로와 임시 패키지 디렉터리는 이 검증 실행의 경로입니다.

## 동일성의 범위

복원 후 새 저장소에서 빌드한 EXE와 공개 EXE는 **COFF 타임스탬프와 IMAGE_DEBUG_DIRECTORY 타임스탬프 두 필드를 제외한 모든 바이트가 일치**합니다. 실행 코드, 데이터, 임베디드 이미지/음원, 한국어 리소스, 저장·업데이트 코드가 일치합니다. 두 필드가 가리키는 위치는 파일 오프셋 128, 1,374,212이고 각각 4바이트입니다. 빌드 시각이 달라 파일 전체의 SHA256은 다릅니다. 공개 EXE 자체와 완전히 같은 해시를 얻었다고 주장하지 않습니다. 비교를 맞추기 위해 EXE를 사후 수정하지 않았습니다.

재검증은 정식 ZIP과 v1.9.0 공식 피드를 내려받아 다음을 실행합니다. 현재 공식 latest가 향후 버전으로 변경되면 이 도구는 의도적으로 실패하므로 v1.9.0 릴리스의 `latest.txt`를 사용하세요.

```bash
curl -fL -o .cache/v19.zip https://github.com/cho-woo/yeopjari-cat/releases/download/v1.9.0/YeopjariCat-Windows-1.9.0.zip
curl -fL -o .cache/v19-latest.txt https://github.com/cho-woo/yeopjari-cat/releases/download/v1.9.0/latest.txt
python3 tools/verify_v19_baseline.py --public-zip .cache/v19.zip --public-feed .cache/v19-latest.txt
```

비교 도구는 ZIP·피드의 고정 체크섬부터 검사하고 공개 ZIP의 EXE와 피드의 버전·크기·해시·URL을 대조합니다. EXE 전체 비교에서 허용하는 것은 위 타임스탬프 필드뿐입니다. 다른 코드/데이터 차이는 실패합니다. 미래 버전의 기능 변경에는 이 v1.9.0 동일성 검사를 적용하지 마세요.

## 남은 범위

저장 형식·사용자 경로·성격 파생 알고리즘은 바뀌지 않아 새 마이그레이션은 필요하지 않습니다. 기존 레거시 읽기·백업·복구 로직은 원본 그대로입니다. 실제 개인 저장 기록은 열거나 수정하지 않았습니다.

실제 Windows GUI, 창 사이 이동, 소리 재생, 실행 중 업데이트의 파일 교체·재시작은 Linux에서 실행 검증하지 않았습니다. 이번에는 GitHub Release를 만들거나 기존 v1.9.0을 덮어쓰지 않았습니다. 활성 CI는 검사·아티팩트 생성만 수행합니다. 원격 푸시·GitHub Actions 실행·새 클라우드 작업의 스냅샷 복원도 이 로컬 검증 결과에 포함하지 않습니다.
